# 墨研小说系统 · 产品需求文档（PRD）

> 版本：v1.0 | 日期：2026-07-19 | 状态：初稿

---

## 一、产品概述

### 1.1 产品定位

墨研小说系统是一个 **AI 驱动的小说创作全流程平台**，将"选题 → 规划 → 创作 → 审核 → 改编 → 导出"整条内容生产管线整合为可视化 Web 工具，服务写手、编剧、编辑和内容团队。

### 1.2 核心价值

| 痛点 | 解决方案 |
|------|---------|
| 长篇创作记忆衰减，前后矛盾 | 分层记忆系统 + 进度追踪 + 自动一致性检查 |
| AI 辅助写作 AI 味太重 | 多风格引擎 + 去 AI 味检测 + 自然度评分 |
| 创作流程碎片化 | 一站式从选题到交付，统一项目文件管理 |
| 审稿标准不统一，效率低 | 10 维自动审核 + 分级打分 + 模板化反馈 |
| 剧本/漫剧改编损耗大 | 结构化改编方法论内置，冲突拆解自动化 |

### 1.3 产品边界

**包含**：小说/剧本/漫剧的创作、规划、审核、改编、导出。
**不包含**：AI 视频生成（由下游 Seedance 平台完成）、AI 图片生成（由下游 Nanobanana 等工具完成）、视频/图片素材管理。

---

## 二、目标用户

| 角色 | 描述 | 核心需求 |
|------|------|---------|
| **写手/作者** | 独立创作小说、短剧剧本、漫剧剧本 | 快速创作、AI 辅助、质量自检、防遗忘 |
| **编剧/主审** | 审核写手稿件、管理写手团队 | 批量审稿、标准化评分、写手分级管理 |
| **改编编剧** | 将长篇小说改编为剧本/漫剧 | 剧情拆解、冲突提取、格式转化 |
| **内容团队管理者** | 统筹多个项目、追踪进度 | 项目总览、进度看板、产能统计 |

## 三、功能模块总览

系统按小说创作生命周期划分为 **6 大核心模块 + 2 个支撑模块**：

```
┌─────────────────────────────────────────────────────────┐
│                    墨研小说系统                           │
├──────────┬──────────┬──────────┬──────────┬─────────────┤
│  ①选题   │  ②规划   │  ③创作   │  ④审核   │  ⑤改编导出  │
│  工作室  │  工作室  │  工作室  │  工作室  │   工作室    │
├──────────┴──────────┴──────────┴──────────┴─────────────┤
│              ⑥ 项目管理（仪表盘 / 进度 / 文件）          │
│              ⑦ 资产库（角色 / 设定 / 模板 / 提示词）     │
└─────────────────────────────────────────────────────────┘
```

### 模块一：选题工作室（Pre-writing）

#### F1.1 市场扫榜

| 编号 | 功能 | 描述 |
|------|------|------|
| F1.1.1 | AI 联网扫榜 | 自动抓取番茄/起点/晋江等平台热榜，生成扫榜报告（书名规律/简介结构/开篇模式/读者评论分析） |
| F1.1.2 | 手动扫榜引导 | 提供扫榜模板和方法论指导，用户手动录入数据后 AI 汇总分析 |
| F1.1.3 | 扫榜报告管理 | 历史扫榜报告存档、对比、检索 |
| F1.1.4 | 趋势热词 | 当前热门题材、标签、爽点类型的趋势可视化 |

**来源 Skill**：novel-writing（market-research.md、genre-database.md）

#### F1.2 选题构思

| 编号 | 功能 | 描述 |
|------|------|------|
| F1.2.1 | 题材选择向导 | 交互式点选：平台 → 题材 → 爽点偏好 → 风格，AI 推荐最佳组合 |
| F1.2.2 | 批量概念生成 | 一键生成 6-12 个选题概念（含剧名/题材标签/一句话梗概/核心爽感/受众/全球通用性） |
| F1.2.3 | 创作模式选择 | 支持 6 种模式：长篇小说 / 短篇小说(5章) / 国内短剧 / 海外仿真人短剧 / 海外AI短剧 / 漫剧(国内+海外) |
| F1.2.4 | 选题对比评估 | 多选题横向对比（市场热度/差异化/可操作性/受众匹配），辅助决策 |

**来源 Skill**：short-drama（题材提报）、novel-writing（风格确认）、comic-drama（视觉风格选择）

#### F1.3 风格确认

| 编号 | 功能 | 描述 |
|------|------|------|
| F1.3.1 | 风格点选向导 | 平台偏好 → 题材偏好 → 爽点偏好 → 写作风格，3 轮交互式点选 |

| F1.3.3 | 风格样本分析 | 上传样本文本，AI 提取语言特征生成个性化风格指南 |
| F1.3.4 | 视觉风格选择 | （漫剧/短剧模式）6 种风格可选：3D CG / 2D赛璐璐 / 水墨国风 / 厚涂写实 / 美漫赛博朋克 / 真人写实 |

**来源 Skill**：novel-writing（writing-style）、comic-drama（visual-style.md）

### 模块三：创作工作室（Writing）

#### F3.1 章节创作

| 编号 | 功能 | 描述 |
|------|------|------|
| F3.1.1 | 智能创作面板 | 分屏布局：左侧编辑区 + 右侧参考资料（大纲/角色/上集摘要/伏笔清单） |

| F3.1.6 | 字数/节奏实时监测 | 实时显示字数、预估时长、爽点间距、情绪颜色 |

**来源 Skill**：novel-writing（章节创作）、comic-drama（episode-writing、visual-writing）

| F3.2.5 | AI 画面可行性提示 | （漫剧模式）标记 AI 难以实现的画面（红灯），提供替代写法 |

**来源 Skill**：novel-writing（防遗忘机制）、comic-drama（ai-awareness、visual-writing）、short-drama（episode-writing）

**来源 Skill**：novel-writing（progress-tracking）

## 五、写作流程定义

系统将不同创作模式的流程标准化为以下流水线：

### 5.1 长篇小说模式

```
扫榜(可选) → 风格确认 → 小说设定 → 故事大纲 → 角色开发
→ 创建进度追踪 → [章节细纲 → 章节创作 → 更新追踪] × N章
→ 审核 → 导出
```

### 5.2 短篇小说模式（5章）

```
风格确认 → 核心梗概 → 角色小传 → 5章大纲
→ [第1章(起) → 第2章(承) → 第3章(承) → 第4章(转) → 第5章(合)]
→ 自检 → 导出
```

### 5.3 短剧剧本模式（国内/海外）

```
模式选择 → 题材选择 → 创作方案 → 角色开发 → 分集目录(50-70集)
→ [分集创作 × N集] → 自检 → 合规审核 → 一审/二审材料打包导出
```

### 5.4 漫剧剧本模式

```
模式选择(国内/海外) → 题材选择 → 视觉风格选择 → 创作方案
→ 角色开发(含视觉锚点) → 分集目录(50-70集)
→ [分集创作(精细画面拆分) × N集] → AI画面可行性自检 → 导出
```

### 5.5 改编模式（小说→剧本）

```
上传小说 → 剧情拆解(每批6章) → 剧情地图 → 质检
→ [单集剧本创作 → 质检] × N集 → 导出
```

### 5.6 扒剧本模式（视频→剧本）

```
上传视频 → 音频转写 + OCR → Clean Timeline → 角色指南
→ 样稿验收 → 批量生产 → 交付核查
```

### 5.7 洗稿模式（重构交付）

```
上传原稿 → DNA提取 → 避抄袭改造 → 题名设计
→ 30集节奏搭建 → 正文创作 → 质检 → DOCX交付
```

## 六、数据模型（核心实体）

```
Project（项目）
  ├── id, name, mode, visual_style, target_medium
  ├── status, progress, created_at, updated_at
  │
  ├── NovelSetting（小说设定）1:1
  ├── StyleGuide（风格指南）1:1
  ├── StoryOutline（故事大纲）1:1
  │
  ├── Character[]（角色）1:N
  │   ├── id, project_id, name, alias, identity
  │   ├── appearance, personality, background
  │   ├── visual_anchor (发型/标志色/配饰/体型/关键词)
  │   ├── arc_stages[] (角色弧线阶段)
  │   └── relationships[] (关系: target_char, type, description)
  │
  ├── Scene[]（场景）1:N
  │   ├── id, project_id, name, type, size
  │   ├── atmosphere, elements, props, lighting, color
  │   └── prompt (参考图提示词)
  │
  ├── Chapter[]（章节/分集）1:N
  │   ├── id, project_id, number, title
  │   ├── status (outline/draft/review/done)
  │   ├── word_count, duration_estimate
  │   ├── conflict_summary, hook_type
  │   └── content (正文)
  │
  ├── Foreshadowing[]（伏笔）1:N
  │   ├── id, content, plant_chapter, plan_recycle_chapter
  │   ├── actual_recycle_chapter, status, priority
  │
  ├── Review[]（审核记录）1:N
  │   ├── id, chapter_id, reviewer_id
  │   ├── scores (JSON: 8维度分数)
  │   ├── grade (A/B/C/D), issues[], suggestions[]
  │
  └── Asset[]（资产引用）N:N
      ├── id, type (character/scene/template), source_project_id
      └── reference_id
```

## 七、非功能性需求

### 7.1 性能
- 章节编辑器打开 < 2 秒（含上下文加载）
- AI 生成响应时间 < 30 秒（流式输出）
- 批量审稿 10 本以内 < 5 分钟

### 7.2 安全
- 用户数据隔离（多租户）
- 项目内容加密存储
- API Key 安全存储

### 7.3 可用性
- 所有 AI 操作支持流式输出（实时看到生成过程）
- 关键操作有撤销/回滚能力
- 适配桌面端为主（创作场景），移动端可查看进度

### 7.4 扩展性
- 创作模式可插拔（新增模式只需添加流程配置文件）
- 审核维度可配置
- 模板系统支持用户自定义
