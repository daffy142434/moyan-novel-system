## 一、产品概述

### 1.1 产品定位

墨研小说系统是一款面向个人作者、写手、编剧和内容创作者的 **AI 小说与剧本创作 Web 产品**。

产品通过项目化、页面化的网页界面，帮助用户完成选题、风格、设定、大纲、人物、目录、正文、审稿、改编和导出的完整创作过程。不同创作类型拥有不同的页面流程和创作规则。

现有创作/审稿 Skill 是产品功能的内部能力来源：

- Skill 中的阶段，转换为网页端中的功能页面或页面步骤；
- Skill 中需要用户选择、输入或确认的地方，转换为网页端交互节点；
- Skill 中的方法、规则、模板和示例，作为对应步骤调用大模型时的补充提示词；
- Skill 中要求读取的上游文档，转换为系统自动注入的项目上下文；
- Skill 中要求生成的文件，转换为系统内可编辑、可保存、可导出的项目内容；
- Skill 中的命令，例如 `/故事大纲`、`~分集`，转换为网页端菜单、按钮和操作，不要求用户记忆命令。

### 1.2 一句话说明

用户在浏览器中选择创作类型，墨研按照对应 Skill 的专业流程一步步引导完成作品，并将确认后的内容、版本和生成记录安全保存到服务端。

### 1.3 产品核心价值

| 用户问题 | 墨研的解决方案 |
|---|---|
| 不知道小说应该从哪里开始 | 按作品类型提供专业、清晰的页面流程 |
| 普通 AI 对话缺少写作方法 | 每个功能背后加载对应 Skill 方法、规则和示例 |
| 长篇写到后面忘记人物和伏笔 | 自动维护设定、角色、章节摘要、状态和伏笔记忆 |
| AI 生成结果千篇一律 | 每一步都可调整提示词、风格和模型参数 |
| 创作资料散落在多个文件和对话中 | 以云端项目为单位统一保存内容、步骤和版本 |
| 不知道作品质量是否合格 | 提供写手自查、专业审稿、一致性和 AI 味检查 |
| 小说转短剧/漫剧工作量大 | 提供结构化拆解、剧情地图和逐集改编功能 |
| 生成消耗不可控 | 展示会员权益、用量、生成消耗和剩余额度 |

### 1.4 产品形态

- 最终主产品为通过浏览器访问的 To C Web 应用，首期优先桌面浏览器体验；
- 网页端承担页面交互、编辑、步骤展示、流式结果展示和用户确认；
- 服务端承担账号、会员、项目、版本、上下文、AI 调用编排、提示词/Skill 配置、用量和订单；
- 项目正文、设定、大纲、角色、审核结果和版本统一存储在服务端；
- PostgreSQL 保存业务关系和必要结构化内容，对象存储保存上传文件、导出文件和大型快照；
- 桌面客户端作为未来备选形态，首期不与 Web 双线开发；
- 用户无需接触 Skill 文件、工作流配置或开发概念；
- Skill 管理、提示词默认配置和模型配置属于内部运营后台能力。

### 1.5 产品边界

**产品包含：**

- 用户注册、登录、个人中心； P0
- 会员、套餐、权益、用量和订单能力； P1
- 小说/剧本项目创建和管理；P0+
- 多种创作类型的专属页面流程；P0
- AI 生成、续写、改写、审稿和改编；P0+
- 步骤级提示词调整；P0
- 项目内容、版本、上下文和记忆管理；P1
- Markdown、纯文本、DOCX、PDF 等导出；P2
- 后续接入联网分析、音视频转写和 OCR。P3
- 云端项目、内容、版本、生成记录和备份恢复；P0+
- 服务端统一模型网关、生成队列和流式返回；P0+
- 平台模型通道、用量归属和额度记录；P0+
- 数据导出和账号数据删除能力；P1

**产品不包含：**

- AI 图片和视频成片生成；
- 未经授权的平台数据抓取；
- 无版权或无使用权材料的仿写、复制；
- 对平台过稿、商业收益或内容合规结果作绝对保证。
- P0 阶段的多人实时协作；
- P0 阶段的 Windows/macOS 桌面客户端；
- 用户在浏览器中直接保存平台模型 API Key。

### 1.6 核心内容优先级

本项目按以下顺序进行产品设计、原型、开发和验收。当前后需求发生冲突、工期不足或需要取舍时，必须优先保证序号更靠前的内容。

| 优先顺序 | 核心内容 | 当前阶段要求 | 不应抢占的工作 |
|---|---|---|---|
| **第一优先级** | To C 网页端与页面功能 | 先完成用户能理解、能进入、能操作、能保存和能继续的完整网页体验 | 不先做通用工作流编辑器、Skill 管理器或复杂运营后台 |
| **第二优先级** | Skill 驱动的创作核心能力 | 各产品模块和页面流程严格按对应 Skill 实现，确保生成质量、上下文和用户确认节点准确 | 不用一套通用聊天提示词冒充不同创作功能 |
| **第三优先级** | Skill 外层包装与结构化模型协议 | 为网页功能提供稳定的请求包装、固定返回字段、Schema 校验、流式解析和异常修复 | 不把协议本身做成用户可见的独立产品 |
| **第四优先级** | 会员、收费、订单及增长业务 | 当前阶段完成数据结构、权益检查点和接口预留；核心创作闭环稳定后再正式开发收费页面和支付 | 不因支付、优惠活动或复杂计费推迟核心创作功能上线 |

#### 优先级执行解释

1. **先有可用网页端，再接完整 AI 能力**：可以先用模拟数据完成页面交互，但最终验收必须接入真实生成。
2. **按功能标注落实顺序**：P0 先完成五章短篇、爽文短剧、AI 漫剧和审稿；P1 再做改编；P2 再做长篇、资产库和高级导出；P3 最后做媒体能力。
3. **结构化协议随核心 AI 功能一起建设**：它不是独立阶段，但在真实模型接入前必须完成，否则页面无法稳定使用模型结果。
4. **收费能力后置但数据不返工**：首期不要求真实支付；服务端预留用户、权益、订单、生成用量和结算关联字段。
5. **内部工具服从网页业务**：运营后台只实现账号、授权、Prompt/Skill 发布和首期模型接入所必需的最小功能。

## 二、目标用户

| 用户类型 | 主要需求 | 典型使用功能 |
|---|---|---|
| 新手作者 | 不懂方法，希望系统带着写 | 选题引导、设定、大纲、人物、章节生成 |

| 内容制作人员 | 视频还原剧本或结构级重构 | 转写、OCR、样稿验收、批量生产、交付导出 |

## 三、产品设计原则

### 3.1 网页端页面功能优先

产品首先是一套完整的网页端功能。用户通过导航、卡片、表单、编辑器、步骤条和按钮使用产品，而不是通过输入 Skill 指令使用产品。

### 3.2 Skill 驱动实现

每个创作页面必须明确对应的 Skill 来源、上下文、提示词和输出要求。页面不能只有相同的“输入一段话 → AI 生成”逻辑，再换不同标题冒充不同功能。

### 3.3 不同类型使用不同流程

长篇、固定五章短篇、短剧、漫剧、审稿和改编拥有独立流程。共用页面组件可以复用，但步骤顺序、输入内容、提示词和生成规则必须按对应 Skill 实现。

### 3.4 用户确认驱动推进

Skill 流程中需要用户确认的阶段，必须在网页端表现为可进入、可编辑、可确认的步骤页面。用户确认后，当前结果才成为后续功能的正式上下文。

### 3.5 AI 辅助而非黑盒替代

用户随时可以修改输入、提示词和生成内容。系统要展示 AI 使用了哪些项目资料，并允许用户选择重新生成、生成多个方案或直接人工编辑。

### 3.6 服务端统一持久化

Skill 中使用 Markdown 文件保存上下文的做法，在产品中转换为服务端项目内容、元数据和版本记录。用户退出页面或更换设备后，重新登录仍能恢复项目状态。

确认后的正文、大纲、角色和报告由服务端统一保存。PostgreSQL 负责业务关系、结构化内容和版本索引；对象存储负责上传文件、导出文件和大型不可变快照；缓存和队列不得成为唯一数据来源。

- 导出；

### F0.4 项目步骤条

每类创作项目顶部或左侧显示专属步骤条：

- 展示完整步骤、当前步骤和完成进度；
- 已确认步骤可返回查看和修改；
- 未满足前置条件的步骤不可直接生成；
- 可选步骤显示“可跳过”；
- 上游内容变化后，下游步骤显示“需要复核”；
- 章节和分集使用一个阶段入口，并在阶段内展示多个子项；
- 步骤名称使用用户能理解的业务语言，不显示 Skill 指令。

步骤状态统一为：未开始、可开始、编辑中、生成中、待确认、已完成、已跳过、需复核、执行失败。

### F0.5 AI 生成与结果确认

所有 AI 创作页面统一支持：

1. 填写或选择本步骤资料；
2. 查看系统即将参考的项目内容；
3. 调整当前步骤提示词；
4. 点击生成并查看流式内容；
5. 停止生成；
6. 重新生成或生成多个方案；
7. 对比候选结果；
8. 直接编辑 AI 结果；
9. 保存草稿；
10. 确认当前结果并进入下一步。

只有“已确认”的结果会自动提供给后续步骤。重新生成不得覆盖用户已确认或人工编辑的版本。

模型返回内容必须先通过系统定义的结构化协议解析和校验，再进入结果编辑区。页面不得直接依赖模型的一整段自由文本判断标题、正文、是否缺少输入或下一步操作。

### F0.7 提示词调整

每个 AI 步骤页面提供“AI 提示词”面板，默认折叠，普通用户可以直接使用系统默认值。

用户可操作：

- 查看当前步骤默认的任务说明；
- 添加自己的创作要求；
- 修改风格、重点、禁忌和输出要求；
- 保存为当前项目的步骤默认值；
- 仅本次使用；
- 恢复系统默认；
- 查看历史版本并回滚。

系统默认提示词由对应 Skill 内容整理而来。用户不需要看到 Skill 文件路径和技术拼接过程，但可以看到易于理解的提示词内容和本次参考资料清单。

为避免误操作，安全规则、账号规则和平台合规规则不可被用户删除。

### F0.8 内容与版本管理

项目内容包括：风格指南、设定、大纲、角色、关系、目录、章节、分集、摘要、伏笔、审核报告和导出文件。

- 每次 AI 生成和人工修改保留版本；
- 用户可以给重要版本命名；
- 支持对比和恢复；
- 修改上游内容时提示会影响哪些下游内容；
- 用户决定保留现状、仅标记复核或重新生成下游内容；
- 所有重要内容都可在“项目内容”页集中查看。

### F0.9 消息与任务中心

- 长任务完成、失败或等待确认时通知用户；
- 显示正在执行和排队中的任务；
- 支持取消尚未开始或正在执行的允许取消任务；
- 显示失败原因、是否扣除额度和重试入口；
- 批量审稿、批量分集和视频处理可在用户离开页面后继续运行。

### F0.10 云端内容与备份

- 新建项目后立即在服务端创建项目、初始步骤和内容空间；
- 正文、设定、大纲、角色、审核结果和确认版本保存在服务端；
- 上传文件、导出文件和大型快照保存到私有对象存储，通过短时签名地址访问；
- 编辑过程自动保存草稿，保存失败必须明确提示，不得显示虚假成功状态；
- 每次 AI 生成、人工确认和重要修改保留版本，可比较和恢复；
- 数据库执行自动备份和时间点恢复，对象存储根据业务等级设置版本与生命周期；
- 用户可以导出项目数据，并可按隐私规则申请删除账号和项目。

### F0.11 服务端 AI 接入

网页端只向墨研服务端提交业务输入，不直接接触供应商密钥。服务端完成：

- 用户身份、权益、额度和并发校验；
- 当前步骤 Skill、默认提示词、用户覆盖和项目上下文组装；
- 模型选择、超时、重试、限流和供应商降级；
- 结构化响应解析、Schema 校验和一次结构修复；
- 通过 SSE 向页面转发生成增量；
- 记录运行状态、真实用量、供应商成本和结算事实。

P0+ 使用平台统一模型通道。BYOK、本地模型和桌面客户端直连作为未来可选能力，不进入首期主链路。

当前开发阶段的首个供应商确定为 DeepSeek。核心创作默认按 `deepseek-v4-pro` 设计，摘要和结构修复可按成本测试 `deepseek-v4-flash`；最终路由通过配置决定，不写死在页面。API Key 仅通过服务端本地环境变量注入，绝不进入前端、数据库、文档或代码仓库。

## 六、创作功能模块

### 模块一：选题与风格

#### F1.1 创作类型选择

用户从首页或工作台选择：

- 长篇小说；
- 固定五章短篇；
- 国内下沉短剧；
- 海外仿真人短剧；
- 海外 AI 短剧；
- 国内 AI 漫剧；
- 海外 AI 漫剧；
- 从已有小说改编；
- 审核已有稿件。

选择后加载对应项目创建页面、步骤条、默认提示词和输出规范。

#### F1.2 市场调研

- 长篇小说可选择跳过；
- MVP 支持用户粘贴或上传榜单、书籍和评论资料，AI 按 `market-research.md` 分析；
- 输出书名规律、简介结构、开篇模式、题材趋势和创作建议；
- 自动联网分析需要后续接入合法搜索或数据服务，并显示来源和时间；
- 不允许把模型旧知识标成实时榜单。

#### F1.3 题材与方向选择

根据当前类型展示 Skill 定义的题材和限制：

- 长篇：玄幻、都市、言情、历史、科幻、游戏、军事、悬疑等；
- 五章短篇：现代言情、古代权谋、悬疑、都市职场、奇幻、科幻、武侠、历史架空等；
- 短剧：按国内下沉、海外仿真人、海外 AI 分别展示收稿方向；
- 漫剧：按国内/海外模式展示题材与视觉方向。

系统可生成多个选题方案供对比，用户确认后进入下一页。

#### F1.4 风格确认

- 通过平台、题材、爽点、叙事视角、语言风格等表单引导；
- 支持上传样本文本进行风格分析；
- 生成可编辑的风格指南；
- 风格指南确认后成为后续正文生成的长期上下文；
- 漫剧额外提供视觉风格选择。

**主要 Skill 来源：** `novel-writing`、`short-novel-skill`、`short-drama`、`comic-drama`。

### 模块二：故事规划

#### F2.1 小说设定

- 世界观、时代、地点、社会环境；
- 题材、基调、结局和叙事视角；
- 核心冲突、主角目标、障碍、代价；
- 力量体系、特殊规则或金手指；
- 开篇吸引点和核心爽点；
- 支持 AI 直接生成、表单引导生成和人工编辑。

#### F2.2 故事大纲

- 长篇使用四阶段结构，规划主线、支线、转折和结局；
- 五章短篇使用固定起承转合结构；
- 短剧/漫剧生成创作方案和全剧节奏；
- 大纲可按阶段折叠、拖动和编辑；
- 关键转折、付费卡点、高潮和结局使用明显标记；
- 确认后供角色、目录和正文页面读取。

长篇流程确定为“先故事大纲，后角色开发”。现有长篇 Skill 部分段落存在相反描述，本产品以 Skill 中明确标注的“先有大纲，后做角色，角色服务于情节”为准。

#### F2.3 角色开发

- 创建主角、反派、支持角色和功能角色；
- 管理姓名、身份、外貌、性格、背景、目标、动机、能力和弱点；
- 生成角色弧线；
- 生成和编辑人物关系；
- 漫剧角色额外包含发型、发色、标志色、配饰、体型和视觉关键词；
- 支持角色卡片、详情页和关系图；
- 角色变化可在正文创作后更新。

#### F2.4 目录与节奏

- 长篇支持分卷和章节目录；
- 五章短篇固定生成五章目录；
- 短剧/漫剧生成完整分集目录；
- 每章/集记录标题、核心事件、冲突、爽点、钩子和出场人物；
- 标记重大转折、付费卡点和精细画面重点集；
- 完整目录确认前，短剧/漫剧默认不能进入批量分集创作；
- 用户修改目录后提示受影响的正文。

#### F2.5 伏笔与节奏辅助

- 伏笔新增、计划回收章节、实际回收章节和状态；
- 情绪或节奏曲线；
- 爽点密度和连续同情绪提醒；
- 角色出场频率和场景使用频率；
- 长篇章节细纲；
- 短剧集尾钩子与付费卡点检查。

**主要 Skill 来源：** 长篇和短篇 Skill 的大纲、人物、模板与方法论；短剧和漫剧 Skill 的创作方案、角色开发、节奏、冲突和钩子规则。

### 模块三：正文创作

#### F3.1 长篇章节创作页

页面布局：

- 左侧：卷/章节目录和状态；
- 中间：正文编辑器；
- 右侧：本章细纲、角色、设定、伏笔、最近摘要、AI 提示词；
- 顶部：当前字数、保存状态、AI 用量和章节操作。

每章流程：

```text
本章方向确认
→ 章节细纲（建议，可跳过）
→ 创作前资料检查
→ AI 生成/人工创作
→ 质量检查
→ 用户确认正文
→ 确认章节摘要、角色状态和伏笔变化
→ 下一章
```

第一章前必须建立进度追踪。生成正文前自动参考：风格指南、小说设定、故事大纲、角色档案、人物关系、进度摘要、本章细纲和最近 2—3 章正文。

#### F3.2 五章短篇创作页

固定执行：

```text
大纲确认 → 人物确认 → 五章目录确认
→ 第1章 → 第2章 → 第3章 → 第4章 → 第5章
→ 全文检查 → 导出
```

每章约 2000—3000 字，并根据题材加载不同写作重点。章节页必须读取大纲、人物、目录、写作风格、章节模板和示例。

#### F3.3 短剧分集创作页

- 按制作模式自动使用对应格式、字数和命名规则；
- 创作前读取创作方案、角色档案、分集目录和最近 2—3 集；
- 每集展示核心冲突、爽点、钩子和目标字数；
- 支持单集生成、指定范围批量生成和重写；
- 每集可运行自检和合规检查；
- 国内下沉、海外仿真人和海外 AI 的提示词不能混用。

#### F3.4 漫剧分集创作页

除短剧通用能力外，还需：

- 显示视觉风格和角色视觉锚点；
- 支持精细画面标记、节拍拆分和景别提示；
- 执行 AI 画面可行性检查；
- 对复杂人群、复杂动作、敏感元素和难生成画面给出替代建议；
- 导出结果可交给下游视觉制作团队。

#### F3.5 AI 局部辅助

在正文编辑器中支持：

- 续写；
- 按选中内容改写；
- 更口语、更简洁、更有冲突、更虐或更爽；
- 台词润色与角色语言区分；
- 动作外化；
- 去 AI 味；
- 插入桥段建议；
- 根据审核意见修改。

### 模块四：记忆与一致性

#### F4.1 长篇记忆

采用三层记忆：

- 长期：小说设定、故事大纲、角色档案、人物关系；
- 中期：章节摘要、关键剧情、角色状态、伏笔和大纲执行情况；
- 短期：最近 2—3 章全文。

每章确认后由 AI 提取记忆更新候选，用户可修改并确认。未经用户确认的推断不得直接改写正式角色设定。

#### F4.2 事实与状态管理

- 用户可锁定角色名、关系、能力边界、世界规则等事实；
- 自动检测前后矛盾；
- 记录人物关系变化的时间和原因；
- 记录角色位置、情绪、能力、伤势和持有物；
- 伏笔支持已埋设、待回收、已回收和废弃状态。

#### F4.3 故事回顾

生成已完成内容摘要、主要情节进展、人物变化、伏笔清单和未来方向建议。回顾页面按项目当前正式内容生成，不依赖临时聊天记忆。

### 模块五：审核中心

#### F5.1 写手自查

页面流程：

```text
选择制作模式和审核阶段
→ 上传或选择项目稿件
→ 确认审核范围
→ 十维检查
→ 查看并确认审核报告
→ 按建议修改
→ 重新审核（可选）
```

十个维度：材料完整、格式、题材、节奏、逻辑、上下文、人物、台词、画面可拍性、AI 痕迹。

支持快速审核和完整审核。报告包含结论、必改项、建议项、通过项和逐集明细。

#### F5.2 编剧主审

页面流程：

```text
审稿配置与写手信息
→ 30 秒快速淘汰结果
→ 正式审稿
→ 评分与逐集逐场批注
→ A/B/C/D 结论
→ 退改意见
→ 修改稿复审
```

支持写手等级、历史问题、审稿深度和批量审稿。系统保留初稿、修改稿和审稿报告的对应关系。

#### F5.3 小说专项检查

- AI 味检测；
- 水文比例和主线占比；
- 内容一致性；
- 人物塑造；
- 情节控制；
- 氛围营造；
- 伏笔回收；
- 全书检查。

审核规则来源于对应创作 Skill 的质量标准，不能用短剧格式规则审核小说正文。

### 模块六：改编工具

#### F6.1 小说转短剧/动态漫

```text
导入小说并确认题材和目标模式
→ 每批 6 章剧情拆解
→ 每批质检并由用户确认
→ 完整剧情地图确认
→ 逐集剧本生成与质检
→ 用户确认
→ 导出
```

- 维护剧情点待用/已用状态；
- 维护源章节待处理/已拆解/已转化状态；
- 剧情地图质检和剧本质检最多自动修订三轮；
- 三轮仍未通过时必须交给用户决定；
- 集数根据内容密度自然生成。

#### F6.2 视频扒剧本

```text
上传视频
→ Whisper 时间轴
→ OCR 字幕和身份条
→ Clean Timeline 校正
→ 角色指南
→ 第1集样稿验收
→ 批量生产
→ 交付核查
```

Whisper、OCR 和媒体处理属于工具服务，不是普通大模型提示词。无法确认的身份标记“待核”，禁止补写视频中不存在的内容。

#### F6.3 重构改编

用户页面使用“重构改编”名称，内部兼容原 `short-drama-rewrite-delivery` Skill。

```text
导入原稿和样稿并确认使用权
→ 提取故事 DNA
→ 确认差异化改造方案
→ 选择题名
→ 确认 30 集节奏
→ 逐集创作与质检
→ 全剧终审
→ 导出
```

只保留抽象的情绪、人物功能、冲突结构和爽点逻辑；必须改变人物、关系、职业、背景、场景、事件、对白和表达。系统需提示版权风险并记录用户的材料使用权声明。

### 模块七：导出与交付

#### F7.1 导出格式

- Markdown；
- 纯文本；
- DOCX；
- PDF；
- 按章节或分集批量打包。

#### F7.2 导出页面

用户选择：

- 导出内容范围；
- 使用哪个内容版本；
- 文件格式；
- 字体、字号、行距和标题格式；
- 是否包含设定、大纲、人物、目录、正文和审核报告；
- 文件命名规则。

DOCX/PDF 必须通过文档渲染工具生成并检查，不能由大模型直接输出二进制文件。

#### F7.3 交付包

- 小说全稿包；
- 短剧一审材料包；
- 短剧二审材料包；
- 全剧正文包；
- 改编剧情地图 + 剧本包；
- 审核报告包。

### 模块八：资产库

#### F8.1 角色资产

保存用户选择的角色模板或角色卡，支持复制到新项目。复制后形成新项目版本，不与原项目角色同步变化。

#### F8.2 场景资产

保存场景名称、氛围、元素、道具、灯光、颜色和提示词。支持按题材、标签和项目搜索。

#### F8.3 模板和个人提示词

- 查看系统提供的创作模板；
- 保存用户自己的大纲、人物、章节和剧本模板；
- 保存步骤级个人提示词；
- 从个人模板创建项目；
- 系统模板升级不覆盖用户模板。

#### F8.4 桥段与素材

保存常用桥段、冲突模式、钩子、退稿意见和安全替代表达。资产库属于辅助功能，不代替对应 Skill 的正式步骤。

## 七、不同创作类型的网页流程

### 7.1 长篇小说页面流程

```text
项目创建
→ 市场调研（可跳过）
→ 风格确认
→ 小说设定
→ 故事大纲
→ 角色开发
→ 章节创作中心
   ├─ 本章方向
   ├─ 章节细纲（可跳过）
   ├─ 正文创作
   ├─ 质量检查
   └─ 记忆更新确认
→ 全书检查
→ 导出
```

页面与 Skill 映射：

| 网页页面/步骤 | Skill 主要来源 | 生成或保存内容 |
|---|---|---|
| 市场调研 | `market-research.md`、题材数据库 | 市场调研报告 |
| 风格确认 | 长篇 Skill 风格流程、风格模板 | 风格指南 |
| 小说设定 | 小说设定模板、爆点方法 | 小说设定 |
| 故事大纲 | 大纲模板、情节设计方法 | 故事大纲 |
| 角色开发 | 角色模板、关系模板 | 角色档案、关系图 |
| 章节细纲 | 细纲模板、当前大纲和进度 | 本章细纲 |
| 正文创作 | 章节模板、写作风格、质量规则、上下文 | 章节正文 |
| 质量检查 | `quality-control.md`、`consistency-check.md` | 检查报告 |
| 记忆更新 | 进度追踪模板 | 摘要、角色状态、伏笔和进度 |

### 7.2 固定五章短篇页面流程

```text
项目创建与题材
→ 核心创意/冲突/调性
→ 故事大纲确认
→ 人物小传确认
→ 五章目录确认
→ 第1章
→ 第2章
→ 第3章
→ 第4章
→ 第5章
→ 全文检查
→ 导出
```

大纲、人物、目录和章节页面分别加载短篇 Skill 对应的 method、template、style 和 example。固定五章是该模式的产品规则，不能在没有新增模式的情况下任意改为长篇流程。

### 7.3 爽文短剧页面流程

```text
制作模式
→ 题材和需求
→ 创作方案
→ 角色开发
→ 分集目录
→ 分集创作中心
→ 自检/合规
→ 一审或二审材料
→ 导出
```

制作模式选择会切换题材限制、角色命名、字数、语言、格式和提示词。国内下沉、海外仿真人、海外 AI 是同一产品模块内的不同子模式。

### 7.4 AI 漫剧页面流程

```text
制作模式与题材
→ 视觉风格
→ 创作方案
→ 含视觉锚点的角色开发
→ 分集目录
→ 精细画面分集创作
→ 画面可行性与合规检查
→ 导出
```

### 7.5 审稿页面流程

写手自查和编剧主审是审稿中心的两个独立产品入口，使用不同深度、结果形式和提示词，不能合并为同一个“AI 审核”页面。

### 7.6 改编页面流程

小说转剧本、视频扒剧本和重构改编是改编工具中的三个独立入口。三者输入、工具依赖、流程和交付结果不同。

## 八、Skill 在产品中的内部实现规范

本章属于产品和技术内部规范，不作为普通用户功能展示。

### 8.1 Skill 内容的使用方式

导入或更新 Skill 后，产品/运营人员需要把内容整理为：

- 适用的产品模块和创作模式；
- 对应页面步骤；
- 当前步骤需要的用户输入；
- 需要引用的主 Skill、reference、template 和 example；
- 需要注入的上游项目内容；
- 默认业务提示词；
- 输出结构；
- 自动校验和用户确认规则。

不能在每次调用时无差别发送整套 Skill。应按当前功能页面选择必要内容，避免上下文浪费和规则冲突。

### 8.2 提示词组装

一次页面生成操作的业务提示词由以下内容组成：

1. 当前页面的任务和角色；
2. 对应 Skill 的方法、规则和禁忌；
3. 对应模板；
4. 必要示例；
5. 当前项目已确认的相关内容；
6. 用户在页面填写的信息；
7. 用户保存的项目提示词；
8. 用户本次追加要求；
9. 输出格式和校验要求。

系统保存每次实际使用的提示词、模型、上下文版本和生成结果，以便问题排查和结果复现。

### 8.3 Skill 外层执行包装

现有 Skill 保持创作方法和内容规则不变。在实际调用大模型时，系统必须在 Skill 外层增加统一执行包装，把当前项目、页面步骤、上下文、用户输入和输出协议明确分区。

外层包装的目标：

- 防止 Skill 内容、项目资料和用户输入混成一段不可识别文本；
- 要求模型把 Skill 生成的主要内容放入固定字段；
- 让网页页面能够稳定显示正文、询问缺失信息、展示警告和进入确认状态；
- 让服务端可以按 Schema 校验、保存、重试和审计；
- 保留不同 Skill 的创作差异，同时统一系统接入方式。

每次调用使用以下逻辑结构。实际传给不同模型供应商时，可转换为其支持的 system/user message 或 structured output 格式。

```json
{
  "protocol_version": "moyan.request.v1",
  "request_id": "由服务端生成",
  "project": {
    "project_id": "项目ID",
    "creation_mode": "long_novel",
    "module": "planning",
    "step_key": "story_outline",
    "step_instance": null
  },
  "system_config": {
    "locale": "zh-CN",
    "response_schema": "moyan.response.v1",
    "content_format": "markdown",
    "requires_user_confirmation": true,
    "allow_memory_suggestions": true,
    "safety_policy": "default"
  },
  "skill": {
    "name": "novel-writing",
    "version": "已发布版本",
    "instructions": "当前页面需要使用的Skill正文或整理后的片段",
    "references": [
      {
        "name": "story-outline-template",
        "content": "当前步骤所需模板内容"
      }
    ],
    "examples": []
  },
  "project_context": {
    "artifacts": [],
    "memory": [],
    "recent_content": []
  },
  "user_input": {
    "form_data": {},
    "project_prompt": "用户保存的项目级补充要求",
    "run_prompt": "用户本次追加要求"
  },
  "output_contract": {
    "main_content_field": "result.content",
    "schema": "由当前页面步骤指定的JSON Schema"
  }
}
```

重要约束：

- `skill.instructions` 只放当前页面所需的 Skill 内容，不默认放入完整 Skill 包；
- Skill 引用的模板、方法和示例分别放入对应字段，不能与用户输入混写；
- `project_context` 只放当前步骤声明需要的已确认项目内容；
- `user_input` 明确区分表单数据、项目长期要求和本次临时要求；
- `output_contract` 明确告诉模型主内容必须返回到哪个字段；
- `request_id`、`run_id`、用户身份、会员权益、额度和模型安全配置由服务端生成或控制；
- 页面步骤状态、正式版本写入和下一步解锁由服务端业务规则控制，均不接受模型修改。

### 8.4 统一模型响应协议

无论调用哪个 Skill，模型最终结果都必须符合统一外层结构。Skill 生成的小说正文、大纲、角色档案、剧本或审核报告统一放入 `result.content`。

```json
{
  "protocol_version": "moyan.response.v1",
  "request_id": "与请求一致",
  "status": "success",
  "result": {
    "content_type": "story_outline",
    "content_format": "markdown",
    "title": "《作品名》故事大纲",
    "content": "这里存放按Skill生成的完整主要内容",
    "structured_data": {}
  },
  "interaction": {
    "state": "awaiting_confirmation",
    "message": "大纲已生成，请确认或修改",
    "missing_fields": [],
    "suggested_actions": ["confirm", "edit", "regenerate"]
  },
  "memory_suggestions": [],
  "warnings": []
}
```

#### 8.4.1 固定字段说明

| 字段 | 类型 | 用途 |
|---|---|---|
| `protocol_version` | string | 响应协议版本，便于兼容升级 |
| `request_id` | string | 与本次服务端生成运行关联 |
| `status` | enum | `success`、`needs_input`、`partial`、`blocked` |
| `result.content_type` | string | 大纲、角色、章节、剧本、审核报告等业务类型 |
| `result.content_format` | enum | `markdown`、`plain_text`、`json` |
| `result.title` | string/null | 页面和产物使用的标题 |
| `result.content` | string | **Skill 生成的主要内容固定存放字段** |
| `result.structured_data` | object | 当前步骤需要额外结构化保存的数据 |
| `interaction.state` | enum | 页面应处于待确认、需补充信息或阻塞状态 |
| `interaction.message` | string | 给用户看的简短状态说明 |
| `interaction.missing_fields` | array | 模型认为仍需用户补充的业务字段 |
| `interaction.suggested_actions` | array | 可建议操作，但最终可用按钮由服务端步骤配置决定 |
| `memory_suggestions` | array | 摘要、人物变化、伏笔等记忆更新候选 |
| `warnings` | array | 内容风险、上下文冲突或生成不完整提示 |

#### 8.4.2 不由模型决定的字段

以下信息不能信任模型返回，统一由服务端根据实际调用和业务状态写入运行记录：

- 实际使用的模型和供应商；
- 实际 Token、供应商费用和用户额度扣减；
- 请求开始/结束时间和耗时；
- 用户权限和套餐权益；
- 当前步骤是否真的完成；
- 下一页面是否解锁；
- 内容是否成为正式项目版本；
- Schema 校验结果和服务端业务校验结果。

模型可以建议 `interaction.state` 和操作，但服务端必须结合页面步骤配置、必填项、校验结果和用户确认重新判断。

#### 8.4.3 不同页面的 `structured_data`

统一外层结构不要求所有内容都退化成 Markdown。各页面可为 `result.structured_data` 定义专属 Schema，例如：

- 角色页面：角色数组、属性、关系边；
- 目录页面：章节/分集数组、冲突、爽点、钩子；
- 章节记忆页面：摘要、人物状态变化、伏笔新增与回收；
- 审稿页面：总分、等级、问题位置、严重程度、修改建议；
- 剧情地图页面：剧情点、源章节、目标集数和使用状态。

`result.content` 始终保留一份适合用户阅读和编辑的完整主内容；`structured_data` 用于页面组件展示、数据库查询和后续上下文组装。两者存在冲突时，不得自动猜测，应标记校验失败或交给用户确认。

### 8.5 流式返回协议

为了同时支持流式生成和结构化结果，服务端生成引擎通过 SSE 向网页发送标准事件：

```text
run.started        本次生成已开始
content.delta      result.content 的增量文本
run.progress       工具或复合任务进度
run.warning        可展示的警告
run.completed      携带完整、已校验的最终响应对象
run.failed         携带错误类型和可重试信息
```

前端在收到 `content.delta` 时只用于实时展示，不立即保存为正式产物。只有收到 `run.completed` 且完整响应通过校验后，才能生成候选版本。用户点击确认后，候选版本才转为正式版本。

如果模型供应商支持严格 JSON Schema，优先使用供应商的结构化输出能力；不支持时由服务端生成引擎进行解析和一次结构修复，但对页面仍使用同一响应协议。

### 8.6 解析、校验与异常处理

模型返回后按以下顺序处理：

1. 在受控服务端运行记录中保存供应商原始响应或受限快照，便于排查；
2. 解析为 `moyan.response.v1`；
3. 校验统一外层 Schema；
4. 校验当前页面专属的 `structured_data` Schema；
5. 校验 `result.content` 非空、类型和格式正确；
6. 执行字数、章节数量、必填标题等业务规则；
7. 通过后生成候选产物；
8. 未通过则进行一次结构修复请求；
9. 修复仍失败则标记运行失败，保留原始内容并允许用户重试。

禁止采用以下处理方式：

- 用不稳定的正则表达式从任意自然语言中猜正文；
- JSON 解析失败后仍把错误内容直接写入正式项目；
- 相信模型自报的 Token、费用、权限或完成状态；
- 因为结构错误重复扣除官方通道额度；
- 自动把 `memory_suggestions` 写入正式记忆而不经过配置或用户确认。

### 8.7 页面步骤配置

内部允许用配置管理页面步骤，但不向 To C 用户提供通用工作流编辑器。每个步骤配置至少包含：

- 页面标识和名称；
- 所属产品模块和模式；
- 前置页面；
- 输入表单；
- Skill 内容引用；
- 上下文选择；
- 默认提示词；
- 输出格式；
- 用户确认要求；
- 下一页面；
- 权益要求和官方通道额度规则。

### 8.8 Skill 冲突处理

现有 Skill 可能包含重复、过时或矛盾说明，不能直接把 Skill 原文当作唯一可执行流程。产品发布前由内部人员确定页面流程和最终默认提示词，并记录所依据的 Skill 版本。

### 8.9 工具型步骤

以下功能必须使用专用工具，Skill 只提供处理规则和提示词：

- 实时联网搜索或榜单分析；
- Whisper 音频转写；
- OCR 字幕和身份条识别；
- 视频抽帧和媒体处理；
- DOCX/PDF 渲染；
- 文件打包。

## 九、会员、收费与商业化

### 9.1 商业模式

系统预留以下收费方式：

- 免费体验额度；
- 月度/年度会员；
- 不同等级会员套餐；
- 额外 AI 额度包；
- 特定高级功能或高成本工具按次收费；
- 后续团队版或机构版。

具体价格、套餐名称和支付渠道在商业方案确定后配置，不硬编码在产品逻辑中。

### 9.2 套餐与权益

权益至少支持按以下维度配置：

- 可创建项目数量；
- 可使用的创作类型；
- 每月 AI 额度；
- 可使用的模型档位；
- 单次最大生成字数；
- 并发任务数；
- 批量生成能力；
- 高级审稿能力；
- 导出格式；
- 版本历史保留时长；
- 文件和视频存储空间；
- 客服或优先队列。

### 9.3 用量与额度

- 页面显示剩余额度和预计消耗；
- 生成前检查用户权益和余额；
- 生成成功后按规则扣除；
- 系统失败、供应商失败或无有效输出时自动退回额度；
- 用户主动停止时按实际消耗或产品规则结算，并提前说明；
- 保存每笔额度获取、赠送、冻结、扣除、退回和过期记录；
- 不直接向普通用户展示难理解的底层 Token，可转换为“墨点”等产品额度，同时在明细中说明计费规则。

### 9.4 会员与购买页面

- 当前套餐、到期时间和自动续费状态；
- 套餐权益对比；
- 月付/年付切换；
- 额度包购买；
- 升级、降级、续费和取消；
- 优惠码或活动权益；
- 支付结果页；
- 订单列表和订单详情；
- 发票能力预留；
- 退款/售后入口和规则说明。

### 9.5 功能限制体验

- 用户进入无权限功能时可以查看介绍和示例，不直接进入空白错误页；
- 点击使用时展示所需套餐或额度；
- 生成过程中额度不足时不得产生无法保存的半成品；
- 已付费生成的内容在会员到期后仍允许用户查看和导出，除非服务协议另有明确约定；
- 价格和权益变更不应影响已购买周期内的既有权益。

### 9.6 订单与支付安全

- 订单金额、商品、权益和支付状态由服务端确认；
- 支付回调需要验签和幂等处理；
- 不因用户重复刷新或重复回调发放多份权益；
- 支付成功但权益发放失败时支持自动补偿和人工处理；
- 记录订单、支付、退款和权益发放流水。

## 十二、非功能性需求

### 12.1 性能与可靠性

- 工作台和普通项目页面首屏目标小于 2 秒；
- 章节、分集和版本列表分页或按需加载，不一次返回完整项目正文；
- 模型供应商正常时，流式生成首段内容目标小于 5 秒；
- 生成任务在服务端执行，用户刷新、关闭页面或更换设备后可查询最终状态；
- 编辑器自动保存使用版本号或 ETag 防止静默覆盖；
- 生成运行、确认版本、支付回调、任务重试和额度扣减必须幂等；
- 数据库启用自动备份并定期验证恢复流程；
- 单个 AI 请求失败不得破坏已确认内容。

### 12.2 安全与隐私

- 用户、项目、文件、生成记录、权益和订单按用户严格隔离；
- 所有项目和文件接口在服务端验证资源归属，不信任网页传入的 `user_id`；
- 平台模型、数据库、对象存储和支付密钥只保存在服务端密钥系统；
- 上传和下载使用鉴权接口或短期签名地址，不公开对象存储桶；
- 明确项目内容会存储在墨研服务器，并在 AI 生成时发送给选定模型供应商；
- 日志不得记录密码、完整密钥和支付敏感信息；
- 生产日志默认不记录完整正文和完整 Prompt，诊断快照需要权限、审计和保留期限；
- 用户可申请导出或删除个人数据；
- 后台敏感操作保留审计记录。

### 12.3 内容与版权安全

- 用户上传材料时确认拥有使用权；
- 对重构改编等高风险功能展示版权提示；
- 支持敏感内容检查和安全替代表达；
- 不向用户承诺“一定过审”或“一定不侵权”；
- 版权投诉和违规内容有处理流程。

### 12.4 可用性

- 用户不需要学习 Skill 指令；
- 每个页面说明“需要填写什么、AI 会做什么、会生成什么”；
- AI 生成失败提供清楚的重试或退款提示；
- 额度扣除前给出预计消耗；
- 关键内容删除、覆盖、回退前二次确认；
- 首期优先 Chrome、Edge 和 Safari 的桌面浏览器体验；
- 网络中断时保留当前未提交编辑内容，并在恢复后提示重试保存；
- 更换设备登录后可继续访问同一项目和生成任务。

### 12.5 AI 成本控制

- 按页面步骤选择必要 Skill 内容，不发送无关文件；
- 长篇上下文支持摘要、优先级裁剪和后续检索扩展；
- 服务端记录每次生成的真实输入/输出用量、供应商成本和用户额度消耗；
- 支持用户、套餐、模型、功能和供应商维度限流；
- 批量任务控制并发，避免重复生成；
- 支持对固定 Skill 内容使用模型供应商缓存能力。

### 12.6 可扩展性

- 新增创作类型时可配置新的项目页面步骤和 Skill 映射；
- 模型通过统一接口接入；
- 搜索、OCR、Whisper、导出等工具可插拔；
- 套餐、权益和价格可后台配置；
- 预留团队协作、邀请成员和角色权限能力。

## 十四、MVP 范围

### 14.1 必须完成

- 官网、登录注册、用户工作台和项目管理；
- 服务端项目内容、步骤、版本和生成记录保存与恢复；
- 固定五章短篇完整页面流程；
- 爽文短剧、AI 漫剧、写手自查和编剧主审完整页面流程；
- 项目步骤条和确认推进；
- 服务端 AI 流式生成、停止、重试和候选结果；
- Skill 外层请求包装、统一响应字段和 Schema 校验；
- 每个 AI 步骤的用户提示词调整；
- 项目内容编辑、自动保存和版本历史；
- 云端自动保存、版本对比、恢复和项目数据导出；
- 服务端模型网关、生成队列、真实用量和成本记录；
- 为后续收费预留用户权益、用量归属和订单关联字段，但不接真实支付；
- 已发布 Prompt/Skill 快照、运行时版本锁定和最小内部发布能力；
- 本机 PostgreSQL、本地文件存储 Adapter 和基础日志；Redis/BullMQ、云对象存储和正式备份在部署阶段接入。

### 14.2 暂不进入 MVP

- 自动联网扫榜；
- 长篇小说、长篇记忆和资产库；
- 视频转写和 OCR；
- 会员购买页面和真实支付渠道接入；
- 订单、退款、优惠活动和发票；
- 面向用户的正式额度包购买；
- Markdown/纯文本/DOCX/PDF 高级导出；
- 团队协作；
- Windows/macOS 桌面客户端；
- BYOK 和本地模型直连；
- 可视化通用工作流编辑器；
- 用户自行导入或管理 Skill；
- 跨项目大型资产市场。

MVP 以平台统一模型网关作为真实生成主通道。模型供应商密钥只保存在服务端，网页不得获取。服务端保存生成所需上下文、Prompt 快照、标准化结果、真实用量和结算关联；完整日志和原始响应按隐私与保留策略控制。

## 十五、MVP 验收标准

### 15.1 To C 页面体验

- 新用户可以在网页注册登录并进入工作台；
- 用户可以创建云端项目并在另一浏览器或设备继续访问；
- 可以清楚地区分并创建五章短篇、爽文短剧、AI 漫剧或审稿项目；
- 用户无需输入任何 Skill 指令即可完成流程；
- 每个需要用户确认的 Skill 阶段都有对应网页页面或清晰的页面步骤；
- 页面显示当前进度、已完成内容和下一步；
- 刷新、关闭页面或重新登录后能够恢复已保存内容和服务端生成状态。

### 15.2 Skill 实现准确性

- 短篇严格执行：大纲 → 人物 → 五章目录 → 五章正文；
- 短剧、漫剧、写手自查和编剧主审分别执行其 Skill 的专属流程；
- 每个页面调用对应 Skill 的方法、模板和必要示例；
- 不同类型的默认提示词、输入字段和输出格式确实不同；
- 系统保存本次生成实际使用的 Skill 配置和提示词快照。

### 15.3 用户确认和提示词

- AI 结果未确认前不会作为下一页面的正式上下文；
- 用户可以保存草稿、重新生成、人工编辑和确认进入下一步；
- 每个 AI 步骤均可增加或修改提示词；
- 提示词可仅本次使用或保存为当前项目默认；
- 可以恢复系统默认并查看历史版本。

### 15.4 结构化模型返回

- 所有 AI 页面使用统一的请求包装和 `moyan.response.v1` 响应外层；
- Skill 生成的主要内容始终位于 `result.content`；
- 角色、目录、记忆和审核等页面能够同时返回页面专属的 `structured_data`；
- 服务端能够校验统一 Schema 和页面专属 Schema；
- 不合规响应不会写入正式项目，并能自动尝试一次结构修复；
- 流式生成使用 `content.delta` 展示，最终以 `run.completed` 的完整响应为准；
- 模型不能决定真实额度、权限、步骤完成状态或下一页面解锁；
- 每次运行在服务端保存请求包装、受控原始响应、标准化响应和校验结果。

### 15.5 云端保存与恢复

- 新建项目后服务端立即创建项目记录、初始步骤和内容空间；
- 自动保存失败不会覆盖上一有效版本，页面刷新后可恢复已成功保存的草稿；
- 每次确认和重要修改产生可查询版本，支持比较和回退；
- 数据库备份和对象存储生命周期策略已配置并通过恢复演练；
- 用户可以导出项目正文和必要结构化资料；
- 删除项目执行延迟永久删除并清理数据库、对象存储和缓存中的关联数据。

### 15.6 用量与商业化预留

- 每次生成均关联用户、项目、步骤和实际模型用量；
- 系统能够记录平台模型通道的输入、输出、真实成本和生成状态；
- 失败重试不会被记录为多次成功消费；
- 数据模型已预留套餐权益、额度流水和订单关联字段；
- MVP 不以完成支付、购买、退款或复杂计费页面作为上线阻塞条件。

## 十七、修正说明

本版对上一版理解进行了以下校正：

| 上一版偏差 | 本版修正 |
|---|---|
| 把系统描述成通用 Skill/工作流管理产品 | 明确为面向创作者的 To C 小说与剧本创作产品 |
| 把 Skill 管理和工作流配置放在用户核心功能中 | 移到内部运营实现规范，普通用户不可见 |
| 页面被理解为工作流执行器外壳 | 改为完整网页业务模块，Skill 负责功能实现质量 |
| 页面围绕 Workflow、StepRun 等技术概念组织 | 改为工作台、选题、规划、创作、审稿、改编、资产和个人中心 |
| 缺少商业化页面和数据 | 新增会员、套餐、权益、额度、订单、支付和运营后台 |
| 没有明确前台与后台边界 | 区分用户前台、项目页面和运营后台 |
| 提示词功能偏技术化 | 改为页面中的高级创作设置，默认折叠且普通用户可直接使用 |
| 把每个内部动作都可能当成页面节点 | 只把用户需要输入、编辑或确认的阶段表现为页面步骤，自动动作留在页面内部 |
| 模型自由文本不利于系统解析 | 在 Skill 外增加统一请求包装，主要生成内容固定返回到 `result.content`，其余系统信息按 Schema 返回 |
| 曾将桌面客户端确定为当前主产品 | 恢复网页端为开发主线，桌面客户端只作为未来备选方案 |
| 曾将项目正文和生成任务迁移到本地 | 恢复服务端统一存储、生成编排、结构校验、用量记录和备份 |
| 首期以长篇小说作为 MVP 中心 | 按用户指定顺序，P0 先做五章短篇、爽文短剧、AI 漫剧和两类审稿，长篇调整为 P2 |

### 17.1 最终优先顺序确认

```text
To C 网页页面与云端创作体验
→ Skill 驱动的模块功能和创作流程
→ 结构化模型请求/响应协议
→ 会员、收费、订单和增长业务
```

该顺序是开发排期和需求取舍的正式依据。商业化需求必须保留扩展空间，但不得提前取代网页创作体验和 Skill 核心能力成为首期开发中心。
