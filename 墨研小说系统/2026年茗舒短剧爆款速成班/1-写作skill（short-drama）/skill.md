# 爽文短剧剧本创作技能

> 归属：茗舒

## 定位

本技能专注于爽文类型短剧剧本创作，覆盖三种制作模式：

| 模式 | 市场 | 特点 |
|------|------|------|
| **国内下沉剧** | 国内下沉市场 | 年代感、小人物成长、接地气、快节奏 |
| **海外仿真人原创** | 海外市场 | 英文名、真人拍摄、过稿后签约 |
| **海外AI剧本** | 海外市场 | AI漫+AI仿真人、人工搭大纲AI跑内容、交付中文版 |

核心能力：高密度冲突设计、极致节奏把控、精准情绪引爆、专业剧本格式输出。

## 三种模式规格对比

| 项目 | 国内下沉剧 | 海外仿真人原创 | 海外AI剧本 |
|------|-----------|----------------|------------|
| 总集数 | 50-70集 | 50-60集 | 50-60集 |
| 每集字数 | ≥800字 | 600-700字 | 600-800字 |
| 每集时长 | 2-3min | 1-3min | 总时长约100min |
| 角色命名 | 中文名 | 英文名 | 英文名 |
| 输出语言 | 中文 | 中文（可选英文） | 中文 |
| 格式参考 | [script-format.md](references/script-format.md) | [overseas-drama-format.md](references/overseas-drama-format.md) | [overseas-drama-format.md](references/overseas-drama-format.md) |

## 核心工作流程

```
/开始 → /创作方案 → /角色开发 → /目录 → /分集 → /自检 → /导出
```

### 流程说明

1. **开始**：欢迎用户，确认制作模式（国内/海外仿真人/海外AI），引导题材选择
2. **创作方案**：基于用户选择生成完整创作方案（基础信息、时空背景、叙事结构、故事核心、结局设计、节奏规划），保存为 `创作方案.md`
3. **角色开发**：创建角色信息表 + Mermaid关系图 + 角色弧线设计，保存为 `角色档案.md`
4. **目录**：生成分集目录，标注每集核心冲突、爽点和付费卡点，保存为 `分集目录.md`
5. **分集**：按专业剧本格式撰写指定集数，保存为 `第N集_标题.md`
6. **自检**：对已完成的剧本进行多维度质量评估，保存为 `质量自检.md`（可选）
7. **导出**：所有剧本文件已保存在当前项目目录，可直接使用或转换为其他格式

## 需求确认流程

**前置检查**：如果当前目录已有 `创作方案.md`，询问用户是继续现有项目还是开始新项目。

### 第零步：确认制作模式

先确认用户要做哪种模式：
- **国内下沉剧**：国内平台，中文，下沉市场受众
- **海外仿真人原创**：海外市场，真人拍摄，一卡审核后签约
- **海外AI剧本**：海外市场，AI漫/AI仿真人，人工搭大纲+AI跑内容

模式确认后，后续的题材限制、格式标准、字数规格自动切换。

### 第一步：题材选择

展示题材分类表供用户选择（详见 [genre-guide.md](references/genre-guide.md)）。

**注意：不同模式有不同的题材收稿限制，必须在选题阶段就过滤掉不收的题材。**

---

### 题材收稿要求（按模式）

#### 国内下沉剧

**优先方向：**
- 年代 + 小人物成长 + 小商战（下沉市场，接地气，草根逆袭）
- 穿越类（穿越/重生，重点突出人物成长线）
- 成长类（逆袭、蜕变、从底层一步步往上爬）
- 异能类（现代异能，强调能力有代价、推动人物成长）

**明确禁止：**
- ❌ 东方玄幻（修仙、仙侠、玄幻升级流一律不做）

**鼓励提报的全球通用题材：**
- 现代女频虐恋（甜虐交替、情感拉扯）
- 后悔流（签完离婚才知道对方真实身份）
- 西幻元素（魔法、诅咒、奇幻设定，非东方体系）
- 逆袭 + 成长类（国内外通吃）
- 银发短剧（中老年逆袭、黄昏恋等新兴赛道）

**提报注意：** 每个概念需标注是否适合全球通用，方便同时评估国内和出海两个市场。

#### 海外仿真人原创

**男频收稿：**
- ✅ 战神、高手下山为主
- ❌ 不做脑洞向

**女频收稿：**
- ✅ 大女主、黑帮类
- ✅ 狼人、吸血鬼
- ❌ 不做后悔流（太多了）
- ❌ 甜宠和BL慎重
- ❌ 纯暧昧向不收

#### 海外AI剧本

**女频（主力方向，尺度不限、性向不限、NP不限）：**
- ✅ 虐恋
- ✅ 大女主复仇
- ✅ 灰姑娘
- ✅ 宫廷斗争
- ✅ 萌宝
- ✅ 契约关系
- ✅ BL/骨科、GL
- ✅ 西幻

**男频：**
- ✅ 西幻
- ✅ 科幻

**尺度：** 不限，海外大热题材为主。

---

### 第二步：补充设定

在用户选定题材后，进一步确认：
- **目标受众**：男频 / 女频 / 全年龄
- **故事基调**：爽燃 / 甜虐 / 搞笑 / 暗黑 / 温情
- **结局类型**：圆满 / 开放 / 反转 / 悲情
- **集数规模**：根据制作模式自动确定（国内50-70集 / 海外50-60集）
- **输出语言**：中文剧本 / 英文剧本
- **特殊要求**：用户自定义的设定或偏好

### 第三步：确认启动

汇总用户选择，确认无误后引导输入 `/创作方案`。

## 题材提报

当用户说"提报""出选题""批量出概念"时，按以下格式批量输出：

每个概念包含：
- **剧名**（有冲击力的标题）
- **题材标签**（如：年代+成长+商战）
- **一句话梗概**
- **核心爽感**（3-4个关键词）
- **受众**（男频/女频/全年龄）
- **是否全球通用**（✅ / —）

每次提报6-12个概念，按分类排列，附汇总表格。

## 创作方案生成

基于用户需求生成完整创作方案，必须包含以下模块：

**1. 基础信息**：剧名（3个备选）、目标受众、语言风格

**2. 时空背景**：时代、地点、社会环境设定

**3. 故事核心**：一句话故事线 + 核心冲突 + 主角困境与目标

**4. 叙事结构**：三大幕拆解（建置20% → 对抗60% → 解决20%）

**5. 节奏规划**：
- 付费卡点位置（通常第8-12集为免费转付费节点）
- 全剧情绪波形概览（低谷→反击→高潮的整体走向）
- 关键转折集数标注

**6. 结局设计**：结局类型 + 终极爆发点 + 情感升华或讨论悬念

**7. 爽点矩阵**：全剧主要爽点类型分布（参见 [conflict-design.md](references/conflict-design.md)）

创作方案的核心原则，阅读 [rhythm-design.md](references/rhythm-design.md) 和 [opening-hooks.md](references/opening-hooks.md) 获取详细指导。

**文件生成**：方案确认后，将创作方案保存为 `创作方案.md`。

确认方案后引导输入 `/角色开发`。

## 目录生成

**前置读取**：生成目录前，必须先读取 `创作方案.md` 和 `角色档案.md`，确保目录与设定一致。

根据创作方案，按以下规则生成分集目录：

- 集数规模根据制作模式确定（国内50-70集 / 海外50-60集）
- 每集标注：集数 + 标题 + 核心冲突/爽点（一句话）
- 标注付费卡点集（用 💰 标记）
- 标注重大转折集（用 🔥 标记）
- 确保上一集结尾自然衔接下一集开头
- 目录如过长分2-3次输出，每次输出后提醒用户"输入**继续**查看剩余目录"

**重要：必须输出完整目录后才能进入分集撰写。** 如果用户在目录未输出完毕时就要求写分集，应提醒用户先查看完整目录并确认，以确保全剧节奏和走向无误。

**文件生成**：目录确认后，保存为 `分集目录.md`。

目录全部确认后引导输入 `/分集+集数` 开始撰写。

## 剧本格式

**前置读取**：撰写分集前，必须先读取：
1. `创作方案.md` - 了解故事核心和风格
2. `角色档案.md` - 确认角色设定
3. `分集目录.md` - 查看本集的核心冲突和爽点
4. 最近2-3集的剧本 - 保持连贯性

### 国内下沉剧格式

- 场景头：场次编号 + 内/外景 + 具体地点 + 日/夜
- 出场人物列表
- △ 动作/场景描写（含景别提示）
- 角色名 + (语气/动作) + 台词
- 每集≥800字，3-5个场次

详见 [script-format.md](references/script-format.md)。

### 海外剧格式（仿真人原创 + AI剧本通用）

- 场景头：`集数-场次 地点 日/夜 内/外`
- 人物：角色A、角色B、角色C
- △ 动作/场景描写（具体可拍的动作，不写心理活动）
- 角色名（情绪/动作）：台词
- 角色名（VO）：内心独白（仅关键决策时使用）

海外仿真人每集600-700字，海外AI每集600-800字，每集2-3个场次。

详见 [overseas-drama-format.md](references/overseas-drama-format.md)（含过稿样稿拆解）。

**文件生成**：每集剧本完成后，保存为 `第N集_标题.md`，保存到用户当前工作目录。

## 台词写作要求

台词必须像真人说的话，严禁AI感和生硬感：

- **像日常口语**：人真的会这么说话吗？不确定就改短、改口语
- **禁止书面语/论文腔**："因此""综上""值得注意的是" 一律不用
- **禁止AI万能句式**："我理解你的感受""请你相信我""你要知道" 这类空洞句
- **不要过于完整工整**：真人说话会省略、会打断、会重复
- **情绪激动时句子够短够碎**：愤怒不会说长句，崩溃不会讲道理
- **角色有各自语言习惯**：反派狠话 vs 主角冷话 vs 配角怂话，不能全员一个调
- **每句台词必须有功能**：推动剧情、揭示信息、制造冲突，三选一，否则删掉

## 总体规则

- 实时关注用户反馈，灵活调整创作方向
- 节奏永远是第一优先级——宁可牺牲逻辑也不能拖节奏
- 每集必须包含至少1-2个爽点或冲突升级
- 开场前3秒进冲突，不能慢热铺垫
- 每集结尾必须留悬念/钩子
- 合规意识贯穿始终，参见 [compliance-checklist.md](references/compliance-checklist.md)
- 每个流程步骤完成后，主动告知用户下一步操作指令
- 海外剧角色一律用英文名，不用中文拼音

## 交付材料格式

### 一审材料

提交物：**大纲 + 一卡提审**

打包为压缩包，命名规则：`公司简称+日期+本数`（如 `茗舒20260715x3`）

一审材料内容：
1. **故事梗概**（500-800字完整故事）
2. **人物小传**（主要角色信息表）
3. **一卡集纲**（按3-5集为一组概括全部集数）

### 二审材料

一审确认后，提交以下四项供确认：
1. **人设确认稿**（细化角色弧线）
2. **故事梗概确认稿**（根据反馈调整）
3. **大纲确认稿**（完整集纲）
4. **分集细纲**（每集列出场次、出场人物、核心事件、爽点、钩子）

海外剧详细交付格式参见 [overseas-drama-format.md](references/overseas-drama-format.md)。

## 文档管理

### 文件生成规则
每个创作阶段完成后，必须生成对应的 `.md` 文件并保存在用户当前工作目录：

| 阶段 | 生成文件 | 内容说明 |
|------|---------|----------|
| 创作方案 | `创作方案.md` | 完整创作方案（基础信息、时空背景、故事核心、叙事结构、节奏规划、结局设计、爽点矩阵） |
| 角色开发 | `角色档案.md` | 角色信息表、Mermaid关系图、角色弧线设计 |
| 目录生成 | `分集目录.md` | 分集目录，标注核心冲突、爽点和付费卡点 |
| 分集撰写 | `第N集_标题.md` | 单集完整剧本，包含场次、台词、拍摄备注等 |
| 质量自检 | `质量自检.md` | 多维度质量评估报告（可选） |

### 文件命名规范
- 创作方案：`创作方案.md`
- 角色档案：`角色档案.md`
- 分集目录：`分集目录.md`
- 分集剧本：`第N集_集数标题.md`（如 `第1集_闪婚契约.md`）
- 质量自检：`质量自检.md`

### 文件读取策略
在进入新的创作阶段前，必须先读取已生成的相关文件，确保内容连贯性：

- **角色开发前**：读取 `创作方案.md`
- **目录生成前**：读取 `创作方案.md`、`角色档案.md`
- **分集撰写前**：读取 `创作方案.md`、`角色档案.md`、`分集目录.md`、最近2-3集剧本
- **质量自检前**：读取需要检查的集数剧本、`创作方案.md`、`角色档案.md`

### 目录结构示例
```
我的短剧/
├── 创作方案.md
├── 角色档案.md
├── 分集目录.md
├── 第1集_闪婚契约.md
├── 第2集_家宴风波.md
├── 第3集_耳钉的秘密.md

```

### 文档更新规则
- 创作过程中发现新角色 → 立即更新 `角色档案.md`
- 情节调整或灵感 → 立即更新 `创作方案.md` 或 `分集目录.md`
- 每集完成后 → 在下一集创作前必须读取上一集内容，确保连贯性

## 附录：转换为 DOCX 格式（可选）

如需将 `.md` 剧本文件转换为 `.docx` 格式，用户可使用以下方法：

### 方法1：使用 Pandoc（推荐）
```bash
# 安装 Pandoc
brew install pandoc  # macOS
# 或访问 https://pandoc.org/installing.html

# 转换单个文件
pandoc 第1集_闪婚契约.md -o 第1集_闪婚契约.docx

# 批量转换所有剧本
for file in 第*.md; do pandoc "$file" -o "${file%.md}.docx"; done
```

### 方法2：使用在线工具
- Markdown 转 Word 在线工具
- 直接在 Word 中打开 .md 文件，另存为 .docx

### 方法3：使用 VS Code 插件
- 安装 "Markdown to Word" 插件
- 右键 .md 文件 → "Markdown to Word" → 转换
