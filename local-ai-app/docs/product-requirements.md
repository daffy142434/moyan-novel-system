## 1. 产品背景与定位

### 1.1 背景

当前使用大模型的方式主要有两种：

| 方式 | 优点 | 缺点 |
|------|------|------|
| 网页/官方客户端 | 开箱即用 | 不可定制、无法串联工具、受限于厂商 UI |
| 代码库集成（如 Codex） | 高度可控 | 需要编程能力、无图形界面、零散的文件操作 |

缺少一个 **本地运行的、可配置的、带图形界面的 AI 对话客户端**，让非开发者也能：
- 配置和管理多个大模型（DeepSeek / DouBao / Kimi / GLM）
- 每个对话自由选择提示词，也支持全局提示词配置
- 管理和复用自定义提示词模板
- 多轮对话流畅交互

### 1.2 产品定位

**Local AI App** —— 一款本地桌面 AI 对话客户端。

> 多模型多对话，提示词自由配置，让 AI 对话更高效、更可控。

| 核心理念 | 说明 |
|---------|------|
| **多模型** | 支持 DeepSeek（v4-flash / v4-pro）、豆包、Kimi、GLM |
| **对话即容器** | 每个对话独立配置模型和提示词，互不干扰 |
| **两级提示词** | 对话级提示词 + 全局提示词，灵活组合 |
| **本地优先** | 所有配置和对话历史存储在本地 |
| **轻量纯粹** | 极简 UI，专注对话体验 |

### 1.3 目标用户

| 用户类型 | 特征 |
|---------|------|
| 普通知识工作者 | 日常用 AI 写作、翻译、总结，需要 GUI |
| 开发者 | 需要将 AI 集成到工作流中，自定义技能和工具 |
| AI 爱好者 | 想尝试不同模型，对比效果，搭建自己的 AI 工作台 |

## 3. 功能需求

### 3.1 核心功能（P0）

#### 3.1.1 多轮对话

- 多轮对话界面，支持 Markdown 渲染、代码高亮
- 左侧会话列表：新建、切换、删除、重命名、搜索
- 每个对话独立绑定 **模型 + 提示词** 配置
- 支持流式输出（SSE）
- 对话历史本地存储（SQLite）
- 对话导出（Markdown / JSON）

#### 3.1.2 提示词体系（两级配置）

**对话级提示词：**
- 每个对话创建时可选择一个提示词模板
- 对话期间可随时切换提示词
- 切换后后续消息使用新提示词，不影响已有历史

**全局提示词：**
- 在设置中配置，作为所有对话的兜底 System Prompt
- 对话级提示词 + 全局提示词可叠加（对话级优先合并）
- 可通过开关控制是否启用全局提示词

**提示词模板管理：**
- 创建/编辑/删除提示词模板
- 每个模板包含：名称、描述、System Prompt 内容
- 支持变量插值 `{{variable}}`（如 `{{language}}`、`{{tone}}`）
- 模板分类标签
- 导入/导出单个模板文件

**内置提示词模板（预装）：**
- 通用助手（默认）
- 代码专家
- 翻译专家（中英互译）
- 写作助手
- 技术文档撰写
- 角色扮演
- SQL 优化师
- 正则表达式专家
- 故事作家

#### 3.1.3 模型管理

- 支持管理多个模型账户（API Key、Base URL）
- 每个模型可设置：显示名称、API Key、Base URL、Max Tokens、Temperature
- 对话时从已配置的模型中任选使用
- API Key 本地加密存储

**支持的模型：**

| 厂商 | 接入方式 | 默认模型 |
|------|---------|---------|
| **DeepSeek** | OpenAI 兼容 API | `deepseek-v4-flash`, `deepseek-v4-pro` |
| **DouBao（豆包）** | 火山引擎 API | 豆包 Pro / Lite |
| **Kimi（月之暗面）** | OpenAI 兼容 API | moonshot-v1 |
| **GLM（智谱）** | 智谱 API | glm-4-plus / glm-4-flash |

### 3.2 辅助功能（P1）

#### 3.2.1 上下文管理

- 对话上下文中显示当前 Token 估算用量
- 支持手动清空上下文、重新开始
- 长对话上下文窗口超限告警

#### 3.2.2 对话搜索

- 全文搜索历史对话内容
- 按对话标题、模型、提示词筛选

#### 3.2.3 主题切换

- 浅色/深色/跟随系统
- 对话气泡样式选择

### 3.3 扩展功能（P2）

| 功能 | 说明 |
|------|------|
| 多语言界面 | 中/英文界面切换 |
| 对话分享 | 导出为图片或链接 |
| 自定义主题 | 自定义主题色、字体大小 |

## 4. 支持的模型

### 4.1 默认模型

| 模型 ID | 说明 |
|---------|------|
| `deepseek-v4-flash` | 默认对话模型，快速响应，适合日常对话和代码生成 |
| `deepseek-v4-pro` | 增强版，适合复杂推理和深度分析 |

其他 DeepSeek 模型可在设置中添加（如 `deepseek-chat`、`deepseek-reasoner` 等）。

### 4.2 模型配置方式

每个模型需要用户自行配置：

| 厂商 | 配置项 |
|------|--------|
| DeepSeek | API Base URL + API Key + 模型名 |
| 豆包 | 火山引擎 Endpoint ID + API Key |
| Kimi | API Base URL + API Key + 模型名 |
| GLM | API Base URL + API Key + 模型名 |

### 4.3 模型网关层

主进程统一管理 API 调用，提供：

- 统一请求/响应格式（各厂商 API 差异由适配层处理）
- 流式输出标准化（统一为 SSE 格式传给渲染进程）
- Token 用量统计
- 错误处理与重试
- 请求超时控制

| LLM 调用 | **reqwest (Rust)** | 流式 HTTP 请求调用模型 API |
| 加密 | **ring + orion** | API Key 本地加密存储 |

### 6.2 关键页面

#### 对话页
- 左侧会话列表（搜索、新建、删除）
- 右侧聊天区域（流式输出、Markdown 渲染、代码高亮）
- 底部输入框（支持 @ 切换技能）
- 输入框上方显示当前技能和模型
- 右键菜单：复制、引用、重试

#### 技能库
- 卡片网格布局，每个技能一张卡片
- 卡片显示：名称、描述、模型、标签
- 点击进入详情：编辑 YAML / 测试 / 导出
- 从本地文件导入技能

#### 提示词编辑器
- 左侧提示词文件树
- 右侧编辑区（带语法高亮的 YAML 编辑器）
- 变量面板：列出当前模板中所有 `{{variable}}`
- 预览按钮：填充示例值后查看渲染效果
- 版本滑动条：回退到历史版本

#### 工作流编辑器
- 节点拖拽式编辑（类似 Node-RED）
- 每个节点配置：技能+模型+参数
- 连线编排执行顺序
- 运行时可查看每个节点输出

### 6.3 设计原则

- **分栏布局**：侧边栏导航 + 主内容区
- **深色优先**：默认深色主题，代码风格
- **极简主义**：减少视觉噪音，聚焦对话
- **键盘友好**：支持快捷键（Ctrl+Enter 发送、Ctrl+/ 切换技能等）
- **响应式**：支持窗口缩放，窄屏自动折叠侧边栏

## 10. 关键设计决策

### 10.1 为什么 Tauri？

| 方面 | Tauri | Electron |
|------|-------|----------|
| 包体 | ~10MB | ~150MB |
| 内存 | ~50MB | ~200MB |
| 启动速度 | ~1s | ~3s |
| 安全性 | 好（沙箱权限模型） | 一般 |
| 后端性能 | Rust 零成本抽象 | Node.js 解释执行 |

Rust 后端天然适合做 LLM 网关的流式 HTTP 请求处理、加密、数据库操作，性能好且安全。

### 10.2 两级提示词设计

- **全局提示词**：兜底配置，适用于所有对话（如"你是一个 AI 助手"）
- **对话级提示词**：每个对话独立选择，覆盖全局（或与全局合并）

两级设计兼顾通用性和灵活性，用户不需要为每个新对话重复配置通用规则。

### 10.3 为什么先接 DeepSeek

- 性价比高
- API 兼容 OpenAI 格式，适配层代码可复用到其他模型
- 中文能力强
- `deepseek-v4-flash` / `deepseek-v4-pro` 覆盖从快速响应到深度推理的场景
