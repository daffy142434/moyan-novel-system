# 安卓手机内存清理工具 — 产品需求文档

> 版本：v1.0
> 日期：2026-07-16
> 状态：初稿

---

## 1. 产品背景与定位

### 1.1 背景

安卓系统长期使用后会产生大量缓存文件、残留目录、空文件夹、APK 安装包、日志文件等垃圾数据，占用宝贵的存储空间。系统自带的清理功能通常不够彻底，而市面上的第三方清理工具普遍存在以下问题：

- **过度商业化**：广告泛滥、诱导下载其他应用
- **隐私风险**：部分工具会上传用户文件列表
- **功耗高**：后台常驻服务频繁扫描，耗电严重
- **清理不透明**：不展示具体清理了什么，用户失去控制感

### 1.2 产品定位

一款 **轻量、开源、注重隐私** 的安卓存储空间清理工具。核心价值：

- **本地运行**：所有扫描在设备端完成，不上传任何数据
- **透明可控**：每一项可清理内容都展示给用户，由用户决定
- **精准高效**：只清理真正的垃圾，不误删用户重要文件
- **极致轻量**：APK 体积控制在 5MB 以内，无后台常驻

### 1.3 目标用户

| 用户类型 | 特征 |
|---------|------|
| 普通用户 | 手机存储吃紧，需要一键清理释放空间 |
| 进阶用户 | 希望了解手机存储构成，手动筛选特定类型的垃圾 |
| 极客/开发者 | 看重开源、隐私，愿意参与贡献 |

## 2. 功能需求

### 2.1 核心功能（P0）

#### 2.1.1 存储概览

- 展示设备总容量、已用空间、可用空间
- 以环形图或柱状图展示存储构成（应用、图片、视频、音频、文档、缓存、其他）
- 显示"可释放空间"预估值

#### 2.1.2 垃圾文件扫描与清理

支持扫描以下类别：

| 类别 | 说明 | 默认勾选 |
|------|------|---------|
| 应用缓存 | `/Android/data/` 下的缓存目录 + 各应用 `cache` 目录 | ✅ |
| 临时文件 | `/tmp/`, `/cache/`, 系统临时目录 | ✅ |
| 空文件夹 | 无任何文件的空目录 | ✅ |
| 残留目录 | 已卸载应用留下的数据目录 | ✅ |
| APK 安装包 | `Download/` 或其他目录下的 `.apk` 文件 | ✅ |
| 日志文件 | `*.log`、`*.trace` | ✅ |
| 缩略图缓存 | `/DCIM/.thumbnails/` 等 | ✅ |
| 大文件候选 | 用户可自定义阈值的超大文件（默认 > 100MB），供用户判断 | ❌ |

**功能细节：**

- 扫描过程展示进度条、已扫描文件数、已发现垃圾大小
- 扫描结果按类别分组，展示每类数量和大小
- 用户可展开每类查看具体文件路径和大小
- 支持全选/反选/单选
- 清理前弹出确认对话框（可选"不再提示"）
- 清理后展示释放空间报告

#### 2.1.3 文件浏览器

- 基本的文件浏览器，支持按目录浏览
- 支持按大小、日期、类型排序
- 支持长按多选进行批量删除
- 内置回收站功能：删除的文件先移入回收站，可恢复或彻底删除
- 回收站文件超过 7 天自动彻底删除

### 2.2 辅助功能（P1）

#### 2.2.1 应用分析

- 列出所有已安装应用及其占用的存储空间
- 按空间占用排序，帮助用户找到"存储大户"
- 显示应用的缓存大小、数据大小、APK 大小

#### 2.2.2 大文件查找

- 扫描设备中超过用户设定阈值的大文件
- 按大小降序排列
- 支持预览（图片/视频/文档）和删除

#### 2.2.3 重复文件检测

- 基于 MD5/SHA256 哈希检测重复文件
- 分组展示重复文件，方便用户选择性删除
- 可选仅扫描特定目录（如 Download、Pictures）

### 2.3 扩展功能（P2）

- **存储使用趋势**：记录每周存储使用变化，以折线图展示
- **定时提醒**：每周/每月提醒用户进行清理
- **深度清理模式**：扫描并清理系统 OTA 包、Dalvik Cache（需 root 或 Shizuku）
- **文件加密粉碎**：对敏感文件进行覆写删除，防止恢复

## 3. 技术需求

### 3.1 平台兼容性

| 项目 | 要求 |
|------|------|
| 最低 API 级别 | API 26 (Android 8.0 Oreo) |
| 目标 API 级别 | API 34 (Android 14) |
| 架构支持 | arm64-v8a, armeabi-v7a, x86_64 |
| 语言 | Kotlin（主），Java（次要兼容层） |

### 3.2 权限需求

| 权限 | 用途 | 备注 |
|------|------|------|
| `READ_EXTERNAL_STORAGE` | 读取文件清单 | Android 11+ 用 `MANAGE_EXTERNAL_STORAGE` |
| `WRITE_EXTERNAL_STORAGE` | 删除文件 | 同上 |
| `MANAGE_EXTERNAL_STORAGE` | 全文件访问（Android 11+） | 引导用户到系统设置页面授权 |
| `STATISTICS` | 获取应用存储统计 | `UsageStatsManager` |
| `PACKAGE_USAGE_STATS` | 应用使用统计 | 辅助分析 |

**隐私设计：**

- 所有文件扫描结果仅保存在内存中，不落盘、不上传
- 首次启动展示隐私说明页面，明确告知数据只做本地处理
- 开源仓库中的代码可供任何人审计

### 3.3 性能指标

| 指标 | 目标值 |
|------|--------|
| APK 体积 | ≤ 5MB |
| 首次扫描速度 | 每 10 万文件 ≤ 30 秒 |
| 峰值内存占用 | ≤ 80MB |
| 后台影响 | 仅扫描时占用 CPU，清理即停，无后台常驻进程 |
| 电池消耗 | 单次扫描 ≤ 0.5% 电量（典型设备） |

### 3.4 架构设计

```
app/
├── data/                    # 数据层
│   ├── scanner/            # 文件扫描引擎
│   │   ├── CacheScanner    # 缓存扫描
│   │   ├── TempScanner     # 临时文件扫描
│   │   ├── EmptyFolderScanner
│   │   ├── ResidualScanner
│   │   ├── ApkScanner
│   │   ├── LogScanner
│   │   ├── LargeFileScanner
│   │   └── DuplicateScanner
│   ├── model/              # 数据模型
│   ├── repository/         # 仓库层
│   └── database/           # Room 数据库（回收站、趋势等）
├── domain/                  # 领域层
│   ├── usecase/            # 用例
│   └── scheduler/          # 定时任务
├── ui/                      # 表现层
│   ├── main/               # 主页面（存储概览）
│   ├── scan/               # 扫描与清理页面
│   ├── filebrowser/        # 文件浏览器
│   ├── appanalysis/        # 应用分析
│   ├── largefiles/         # 大文件查找
│   ├── duplicates/         # 重复文件
│   ├── recyclebin/         # 回收站
│   └── settings/           # 设置页面
├── service/                 # 服务层
│   └── RecycleBinService   # 回收站管理服务
└── util/                    # 工具类
    ├── FileUtils
    ├── HashUtils
    └── StorageStatsUtils
```

### 3.5 技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| UI 框架 | Jetpack Compose | 现代声明式 UI，减少样板代码 |
| 状态管理 | ViewModel + MutableState | 原生支持，无需额外依赖 |
| 数据库 | Room | 官方推荐，类型安全 |
| 依赖注入 | Hilt | 官方 DI 方案 |
| 文件扫描 | 原生 java.io.File + DocumentFile | 无额外依赖，控制力强 |
| 多线程 | Kotlin Coroutines + Flow | 非阻塞扫描，响应式更新 |
| 构建工具 | Gradle KTS + Version Catalog | 现代化构建配置 |
| 最低支持 | AGP 8.x + Kotlin 2.0+ | 保持工具链最新 |

## 4. UI/UX 需求

### 4.1 设计原则

- **简洁克制**：以信息和功能为主导，不做过度装饰
- **Material Design 3**：遵循 Material You 设计语言，支持主题色跟随系统
- **流畅动画**：扫描进度、页面切换等场景有细腻的过渡动画
- **暗黑模式**：自动跟随系统暗黑模式

### 4.2 页面结构

```
底部导航栏
├── 首页（存储概览）       ← 默认页
│   ├── 存储环形图
│   ├── 可释放空间卡片
│   └── 快速扫描按钮
├── 扫描结果               ← 扫描完成后跳转
│   ├── 类别分组列表
│   ├── 每类可展开查看详情
│   └── 底部清理按钮
├── 浏览                   ← 文件浏览器
│   ├── 目录层级导航
│   ├── 文件列表（图标+名+大小+日期）
│   └── 排序/视图切换
├── 工具                   ← 更多工具
│   ├── 应用分析
│   ├── 大文件查找
│   ├── 重复文件
│   └── 回收站
└── 设置                   ← 设置页面
    ├── 清理排除列表
    ├── 大文件阈值设置
    ├── 回收站保留天数
    ├── 关于/开源许可
    └── 隐私政策
```

### 4.3 关键交互

- **FAB（悬浮按钮）**：首页右下角的"立即扫描"按钮
- **Swipe-to-refresh**：首页下拉刷新存储信息
- **扫描动画**：扫描过程中显示动态圆环 + 实时计数
- **清理动效**：清理完成后显示"爆炸"或"收缩"微动效 + 释放空间数字变化
- **Haptic Feedback**：扫描完成、清理完成等关键事件触发触感反馈

### 4.4 文案风格

- 中文为主，英文为备选，支持系统语言自动切换
- 使用材料设计文案指南，避免技术术语
- 示例："已释放 2.3 GB 空间"而非"已删除 2.3 GB 文件"
- 错误提示友好且提供解决方案："无法访问该目录。您可以在系统设置中授予「所有文件管理权限」"

## 5. 非功能需求

### 5.1 安全性

- 所有删除操作先进入回收站（用户可选"直接删除"）
- 回收站中的文件可完全恢复
- 关键操作（批量删除、清空回收站）需要二次确认
- 避免使用 `Runtime.exec()` 执行 shell 命令
- 严格限制运行时权限申请时机（用户触发相关功能时才申请）

### 5.2 稳定性

- 扫描引擎需处理文件系统访问异常（权限不足、SD 卡拔出等）
- 扫描中断后可继续或重新开始
- 大文件删除操作使用事务机制，失败时回滚
- Crash 上报可选（用户同意后通过 ACRA 等轻量方案上报）

### 5.3 可测试性

- 扫描引擎使用依赖注入，方便单元测试
- 文件操作抽象为接口（`FileOperator`），可注入模拟实现
- 关键算法（重复文件检测、缓存路径匹配）有独立单元测试覆盖
