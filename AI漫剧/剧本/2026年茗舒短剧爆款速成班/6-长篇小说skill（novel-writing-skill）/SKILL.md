# 网文长篇小说创作 Skill

> 归属：茗舒

[技能说明]
    专业的网文长篇小说创作技能包,覆盖从市场调研到章节创作的完整工作流程。通过结构化的文档管理和创作方法论,解决长篇创作中的上下文记忆问题,确保数十万字创作过程中的内容一致性、人物连贯性和情节完整性。

[核心能力]
    - **工作流程管理**:识别当前创作阶段,引导用户完成从市场调研到章节创作的完整流程
    - **文档结构化管理**:通过标准化文档模板管理小说设定、角色信息、大纲规划等核心信息
    - **上下文持久化**:将关键信息固化到文档中,解决长文创作的记忆衰减问题
    - **质量实时监控**:创作过程中实时检测AI味、水文、内容一致性等质量问题
    - **灵活互动创作**:支持用户在任何阶段介入,调整故事发展方向
    - **专业创作指导**:基于网文市场规律和读者心理,提供专业的爆点设计和节奏控制建议

[支持的题材类型]
    - 玄幻修真：修仙、异能、系统流、废材逆袭
    - 都市生活：职场、商战、娱乐圈、重生都市
    - 言情爱情：霸总、甜宠、虐恋、古言现言
    - 历史穿越：架空历史、穿越重生、宫斗宅斗
    - 科幻未来：星际、末日、机甲、赛博朋克
    - 游戏竞技：电竞、虚拟网游、无限流
    - 军事谍战：特种兵、谍战、抗战
    - 悬疑推理：刑侦、灵异、探险

[创作工作流程]
    完整的创作流程分为8个阶段,每个阶段生成对应的文档,确保信息持久化:

    **阶段0:市场调研(可选)**
    - 触发指令:/扫榜引导
    - 主要工作:了解市场热点、分析成功作品、确定创作方向
    - 扫榜方式:
      • 方式1:用户自己扫榜(AI提供平台链接和指南)
      • 方式2:AI协助联网扫榜 ⭐推荐(AI实时抓取并生成报告)
    - 输出文档:market-research-YYYY-MM-DD.md(扫榜报告,与小说项目一起保存)
    - 关键资源:market-research.md

    **阶段1:风格确认**
    - 触发指令:/风格确认
    - 主要工作:确定写作风格、减少AI味、建立语言特色
    - 输出文档:style-guide.md(风格指南)
    - 关键资源:writing-style.md

    **阶段2:小说设定**
    - 触发指令:/小说设定
    - 主要工作:确定类型、基调、世界观、核心冲突
    - 输出文档:novel-setting.md(小说基础设定)
    - 文档模板:templates/novel-setting.md

    **阶段3:故事大纲** ⭐顺序调整
    - 触发指令:/故事大纲
    - 主要工作:规划整体情节、设置转折点、布局主次情节线
    - 输出文档:story-outline.md(故事大纲)
    - 文档模板:templates/story-outline.md
    - **重要**:先有大纲,后做角色,角色服务于情节

    **阶段4:角色开发** ⭐顺序调整
    - 触发指令:/角色开发
    - 主要工作:创建角色档案、人物小传、角色关系链
    - 输出文档:character-profiles.md(角色档案)
    - 文档模板:templates/character-profile.md
    - **包含**:人物小传、角色档案、角色关系图

    **阶段4.5:创建进度追踪** ⭐新增
    - 触发时机:第1章创作**前**必须创建
    - 主要工作:建立进度追踪框架,准备记录创作进度
    - 输出文档:progress-tracking.md(进度追踪)
    - 文档模板:templates/progress-tracking.md
    - **重要性**: 这是长篇创作的"中期记忆",解决遗忘和幻觉的核心文档
    - **创建时机**: 角色开发完成后,第1章细纲**之前**
    - **初始状态**: 创建空文档,建立框架结构
    - **更新频率**: 每章创作完成后必须更新
    - **读取频率**: 每次创作前必须读取
    - **核心功能**:
      - 记录最近章节摘要
      - 追踪待回收伏笔清单
      - 追踪角色状态变化
      - 对比大纲执行情况
      - 提供下次创作前必读

    **阶段6:章节细纲** ⭐重要
    - 触发指令:每一章创作前必须执行
    - 主要工作:规划本章大概走向、核心情节、爽点安排
    - 输出文档:chapter-XXX-outline.md(章节细纲)
    - 文档模板:templates/chapter-outline-template.md
    - **流程**:
      1. AI询问用户是否需要创建细纲
      2. 如果用户选择"需要":创建细纲→用户确认→进入创作
      3. 如果用户选择"跳过":直接进入创作
    - **推荐**:每一章都建议先写细纲,确保情节连贯不跑偏

    **阶段7:章节创作**
    - 触发指令:细纲确认后 或 用户选择跳过细纲
    - 主要工作:创作章节正文内容
    - 输出文档:chapter-XXX.md(章节文件)
    - 文档模板:templates/chapter-template.md
    - 进度追踪:progress-tracking.md(进度追踪)
    - **要求**:严格遵循细纲(如果存在)创作

[执行流程]
    第一步:理解用户请求
        - 识别用户处于哪个创作阶段
        - 识别用户想要执行的具体操作(调研/设定/创作/检查/修改)
        - 确认是否需要读取已有的创作文档

    第二步:读取必要资源
        根据不同阶段读取对应的资源:
        
        **市场调研阶段**:
            1. 读取 market-research.md(扫榜方法和市场分析)
            2. 读取 resources/genre-database.md(题材数据库)
        
        **风格确认阶段**:
            1. 读取 writing-style.md(风格控制方法)
            2. 如果用户上传了样本,分析样本的语言特征
        
        **小说设定阶段**:
            1. 读取 templates/novel-setting.md(设定模板)
            2. 读取 style-guide.md(如果已创建,了解风格要求)
            3. 读取 plot-design.md(爆点设计方法)
        
        **故事大纲阶段**:
            1. 读取 novel-setting.md(基础设定)
            2. 读取 templates/story-outline.md(大纲模板)
            3. 读取 plot-design.md(情节设计方法)
            4. 读取 style-guide.md(风格要求)
            5. **注意**:此时还没有角色档案,大纲主要规划情节走向

        **角色开发阶段**:
            1. 读取 story-outline.md(了解故事情节,根据情节需要创建角色)
            2. 读取 novel-setting.md(了解世界观和设定)
            3. 读取 templates/character-profile.md(角色模板)
            4. 读取 style-guide.md(了解风格要求)

        **章节细纲阶段**:
            1. 读取 story-outline.md(了解整体情节)
            2. 读取 character-profiles.md(了解出场角色)
            3. 读取 progress-tracking.md(创作进度) ⭐重要
            4. 读取 templates/chapter-outline-template.md(细纲模板)
            ⚠️ **检查**: 如果是第1章,必须先确认 progress-tracking.md 已创建

        **章节创作阶段**:
            1. 读取 novel-setting.md(世界观设定)
            2. 读取 story-outline.md(故事大纲)
            3. 读取 character-profiles.md(角色信息)
            4. 读取 character-relationships.md(人物关系图) ⭐NEW
            5. 读取 chapter-XXX-outline.md(本章细纲,如果存在)
            6. 读取 progress-tracking.md(创作进度和已有章节摘要) ⭐强制
               ⚠️ **重要性**: 这是防遗忘和防幻觉的核心文档
               ⚠️ **检查**: 如果是第1章创作前,必须确认此文档已创建
               ⚠️ **更新**: 每章创作完成后必须更新此文档
            7. 读取最近2-3章的完整内容(保持连贯性)
            8. 读取 templates/chapter-template.md(章节模板)
            9. 读取 writing-style.md(风格要求)
            10. 读取 quality-control.md(质量标准)
            11. 读取 plot-design.md(爆点设计,特别是前3章)
        
        **质量检测阶段**:
            1. 读取要检测的章节内容
            2. 读取 quality-control.md(检测标准)
            3. 读取 consistency-check.md(一致性清单)
            4. 读取 novel-setting.md 和 character-profiles.md(对比检查)

    第三步:执行专业创作
        根据不同阶段执行对应的创作任务:
        
        **市场调研**:
            - 询问用户选择扫榜方式(自己扫/AI协助)
            - 方式1:提供扫榜方法和平台链接,指导用户收集数据
            - 方式2:联网获取最新榜单,生成详细分析报告
            - 将扫榜结果保存为market-research-YYYY-MM-DD.md
            - 基于扫榜数据给出创作方向建议
        
        **风格确认**:
            - **识别用户情况**:
              • 情况1:用户基于扫榜结果自主选择题材 → 直接询问风格偏好 → 生成style-guide.md → 进入小说设定
              • 情况2:用户有明确想法,直接说出题材 → 直接询问风格偏好 → 生成style-guide.md → 进入小说设定
              • 情况3:用户需要AI引导选择 → 进入交互式点选流程
            - **情况3的处理流程(使用AskUserQuestion工具)**:
              • 第1轮:AskUserQuestion询问平台偏好(4选项)
              • 第2轮:AskUserQuestion询问题材偏好(4选项)
              • 第3轮:AskUserQuestion询问爽点偏好(4选项)
              • 结果确认:AskUserQuestion综合推荐题材(3选项)
              • 风格选择:AskUserQuestion选择写作风格(4选项)
              • 最终确认:AskUserQuestion题材+风格确认(2选项)
            - **生成style-guide.md**:基于用户选择和templates/style-guide-template.md生成个性化风格指南
            - **明确要求**:语言特征、句式特点、修辞手法、禁止事项
        
        **小说设定**:
            - 引导用户选择类型、基调、结局类型、叙事视角
            - 基于用户选择生成初始创作方案
            - 逐项与用户确认和调整
            - 生成符合templates/novel-setting.md格式的完整设定文档
            - 特别关注:开篇前800字吸引点构思、前三章情节安排、核心爽点设计
        
        **角色开发**:
            - 基于novel-setting.md创建角色档案表格
            - 确保角色丰富度(默认15人,包含主角、反派、支持角色、次要角色、临时角色)
            - 每个角色包含:名称、身份、外貌、性格、背景、目标、能力
            - 生成符合templates/character-profile.md格式的角色档案
            - 可选:生成角色关系图(Mermaid格式)
        
        **故事大纲**:
            - 基于novel-setting.md和character-profiles.md规划情节
            - 采用四阶段结构:起始(20%)、发展(30%)、高潮(30%)、结局(20%)
            - 标注关键转折点、主要情节线、次要情节线
            - 生成符合templates/story-outline.md格式的大纲文档
            - 强调:大纲是指导框架,创作中可灵活调整
        
        **章节创作**:
            - 基于全部上下文文档(setting + characters + outline + recent chapters)
            - 严格遵循style-guide.md的风格要求
            - 应用quality-control.md的质量标准(水文控制、主线占比70%+)
            - 每章不低于3000字
            - 前三章特殊处理:
                • 第1章:前800字高吸引力开场+初始爽点,必须应用plot-design.md中的开篇优化方法
                • 第2章:强化主角特质,读者产生认同
                • 第3章:初步爽点释放,长期伏笔埋设
            - 每章结尾留悬念
            - 生成符合templates/chapter-template.md格式的章节文档
            - 同步更新progress-tracking.md(章节摘要、关键剧情点、伏笔记录)

    第四步:生成和管理文档
        **文档创建**:
            - 每个阶段完成后,必须生成对应的标准化文档
            - 文档严格遵循templates/中定义的格式
            - 文档命名规范:
                • market-research-YYYY-MM-DD.md(市场扫榜报告)
                • novel-setting.md(小说设定)
                • style-guide.md(风格指南)
                • story-outline.md(故事大纲)
                • character-profiles.md(角色档案)
                • character-relationships.md(人物关系图) ⭐NEW
                • chapter-XXX-outline.md(章节细纲,可选,XXX为章节号)
                • chapter_XXX.md(章节正文,XXX为三位数编号)
                • progress-tracking.md(进度追踪)
        
        **文档更新**:
            - **人物关系变化**:立即更新character-relationships.md
              • 触发:角色间关系发生改变(敌对→盟友、陌生→认识)
              • 记录:变化的时间、原因、当前状态、影响范围

            - **角色新发现**:立即更新character-profiles.md
              • 触发:发现角色的新性格、新能力、新背景、新秘密
              • 记录:新增信息、与之前设定的关系

            - **情节调整**:立即更新story-outline.md
              • 触发:临时灵感、用户要求调整情节走向
              • 记录:调整内容、原因、影响范围、后续章节

            - **伏笔埋设**:立即记录到progress-tracking.md
              • 触发:埋下新的伏笔、暗示未来情节
              • 记录:伏笔内容、计划回收章节、重要性级别

            - **新角色出现**:添加到character-profiles.md和character-relationships.md
            - **世界观新设定**:更新novel-setting.md
            - **每章完成**:必须更新progress-tracking.md
        
        **文档读取策略**:
            - 短期记忆:最近2-3章的完整内容
            - 中期记忆:进度追踪文档(章节摘要和关键剧情点)
            - 长期记忆:基础设定、角色档案、故事大纲(全文)
            - 这种分层记忆策略有效解决长文创作的上下文限制问题

    第五步:质量监控与用户反馈
        **实时质量监控**:
            - 章节创作后自动提示用户可用的检测功能
            - /检查AI味:检测AI痕迹,提供改进建议
            - /水文自检:检测水文比例,确保主线占比
            - /内容一致性:检查逻辑、细节、人物、情节的一致性
        
        **用户反馈机制**:
            - 每章完成后询问用户满意度
            - 提供修改选项:
                • 满意 → 继续下一章
                • 需要调整 → 根据反馈修改当前章
                • 想看回顾 → 执行/故事回顾
            - 关键情节转折点:提供2-3个发展方向供用户选择
        
        **灵活互动**:
            - 用户可以在任何时候:
                • 调整故事走向
                • 修改角色设定
                • 添加新角色或情节线
                • 更改写作风格
            - 所有变动同步更新到对应文档

[创作原则]
    - **文档化原则**:
        • 所有关键信息必须固化到文档中
        • 文档是上下文的持久化存储,是长文创作的记忆基石
        • 严格遵循模板格式,便于信息提取和更新

    - **质量优先原则**:
        • 前三章是生死线,必须精雕细琢
        • 第一章前800字决定读者去留,必须应用开篇优化方法
        • 主线剧情占比不低于70%,严格控制水文
        • 实时监控AI味,保持人性化表达

    - **连贯性原则**:
        • 创作新章节前必须读取相关文档
        • 人物行为、世界观设定、情节逻辑必须前后一致
        • 伏笔要记录在progress-tracking.md中,确保回收
        • 角色关系、性格发展要有合理的演变轨迹

    - **市场导向原则**:
        • 了解读者喜好,设计符合市场的爆点
        • 书名、简介、开篇要有吸引力
        • 爽点设计要高频(配置型+人设型+情节型+情感型)
        • 每章结尾留悬念,促进追更

    - **灵活调整原则**:
        • 大纲是指导不是束缚,可根据灵感调整
        • 尊重用户的创意和想法
        • 用户可以在任何时候介入和调整
        • 意外的灵感往往比预设的大纲更精彩

[AI直接生成功能]
    **功能说明**:
    在任何使用AskUserQuestion询问用户的环节,都应该提供"AI直接生成"选项,
    让用户可以跳过问答流程,让AI基于已有设定自动生成内容。

    **触发时机**:
    - 用户不想回答问题,希望AI直接创作
    - 用户没有明确想法,希望AI给出建议
    - 用户想加快创作速度,跳过选择环节

    **AskUserQuestion标准选项模板**:
    ```python
    AskUserQuestion(
        options=[
            # 具体选项1-3个...
            {
                "label": "让AI直接生成",
                "description": "基于已有设定,让AI自动创建完整内容,跳过问答流程"
            },
            {
                "label": "跳过此步骤",
                "description": "暂时跳过,后续需要时再来补充"
            }
        ]
    )
    ```

    **AI直接生成时的逻辑**:
    1. 读取已有的设定文档(novel-setting.md、story-outline.md等)
    2. 基于已有信息,智能推理缺失的内容
    3. 生成完整的内容文档
    4. 展示给用户确认,提供修改机会

    **各阶段的AI直接生成**:
    - **故事大纲**:基于novel-setting.md和style-guide.md生成完整大纲
    - **角色开发**:基于story-outline.md生成需要的角色档案(15个角色)
    - **章节细纲**:基于story-outline.md生成第一章细纲
    - **章节创作**:基于所有文档直接创作章节正文
