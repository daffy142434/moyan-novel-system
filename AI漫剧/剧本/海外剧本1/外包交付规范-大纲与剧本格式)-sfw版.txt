# 外包交付规范：大纲与剧本格式（SFW版）

> 本文档用于对齐外包团队的产出格式（SFW 安全版）。请严格遵守以下规范交付。

---

## 一、交付物清单

每个项目需交付 **3 类文件**：

| 文件 | 数量 | 命名格式 |
|------|------|---------|
| 人物设定 | 1 份 | `characters-{项目标识}.md` |
| 10集大纲 | 1 份 | `outline-{项目标识}.md` |
| 分集剧本 | 10 份 | `script-ep{01~10}-v1-{项目标识}.md` |

**项目标识** = 拼音缩写 + 项目启动日期（YYMMDD），例：`guran-sheying-260713`

---

## 二、硬性约束

- **单集时长** ≤ 2 分钟
- **单集场景**：不限场景数量，可在单集内进行合理的场景切换（但需确保叙事连贯，不宜超过 3 个场景）
- **单集行数**：40–80 行（普通集）；**skip 集需缩短 30%-50%**（约 20–55 行），为后续 nsfw 补充留出空间
- **每集必须有"杀必死"场景**（性张力/视觉冲击/肢体接触型，至少选一）
- **剧本是拍摄脚本**：动作行写镜头能拍到的东西（景别、动作、道具），不写文学修辞

---

## ⭐ 三、【skip】机制（重点）

### 什么是【skip】

`【SKIP】` 是我们处理亲密关系临界点的标准协议。当剧情推进到性行为即将发生的节点时：

1. **铺垫到临界点**（情绪/动作/氛围推到「再往前一步就是」的位置）
2. **写 `【SKIP】`**（一行，独占一行）
3. **紧接 `DISSOLVE TO:`**
4. **跳转到"事后场景"**（时间跳跃后的状态：衣物散落、人物位置变化、对话语气转变）

### 剧本中的写法示范

```markdown
她闭上了眼。

【SKIP】

DISSOLVE TO:

草席上铺着的白色绒毯皱成一团。暮色已经从橘色变成了灰蓝色。

顾染（特写）侧躺在草席上，头枕着卷起来的女仆围裙。
她拿着我的相机翻看回放屏幕。
```

### 关键规则

| 规则 | 说明 |
|------|------|
| **不写过程** | 【SKIP】前后之间的内容是留白，不写任何描述 |
| **事后场景必须写** | SKIP 后面必须紧跟事后状态，不能直接 FADE OUT |
| **事后要有信息增量** | 事后场景不是装饰——必须推进剧情或关系（例：角色说了关键台词、态度发生转变） |
| **每集标记类型** | 剧本头部明确标注 `本集类型：skip集` 或 `本集类型：普通集` |
| **skip 集篇幅要求** | skip 集的 sfw 正文必须比普通集短 30%-50%，因为后续会由 nsfw 团队补充【skip】展开内容 |

## ⭐ 四、大纲中的【skip】规划（重点）

### 必须包含"杀必死/skip 全集规划表"

在大纲的 **第二章节** 放一张总表，提前规划好 10 集中哪些集需要 skip：

```markdown
## 二、杀必死/【skip】全集规划

| 集次 | 涉及角色 | 场景类型 | 是否需要【skip】 |
|------|---------|----------|----------------|
| 第1集 | 女主、男主 | 镜前换衣，视觉冲击 | 否 |
| 第2集 | 女主、男主 | 跨坐大腿拍男友视角 | 否 |
| 第3集 | 女主、男主 | 反锁门提出"肉偿" | **是** |
| 第4集 | 女主、男主 | 近距离调整造型 | 否 |
| 第5集 | 女主、男主 | 沉默注视，代偿成惯例 | **是** |
| ... | ... | ... | ... |
```

### skip 分布原则

- **10 集中安排 4-5 个 skip 集**（不能太密也不能太少）
- **不强制限制 skip 的起始集数**——如果题材需要，第 1 集即可设置 skip 来制造开场爆点（例：倒叙开局、闪回式开场）
- **skip 集之间至少间隔 1 集普通集**（避免连续 skip 导致叙事断裂）
- **每个 skip 必须是感情线的"质变节点"**（不是为了 skip 而 skip，是剧情走到那了必须发生）

### 分集大纲中的标注

每集大纲末尾有一行，格式为：

```
**杀必死/【skip】**：涉及角色 / 场景描述 / 是否skip
```

示例：
```
**杀必死/【skip】**：顾染、我 / 反锁民宿门，壁咚更衣镜前提出"肉偿" / **是**（铺垫到第三颗扣子 → 【SKIP】 → 清晨事后场景）
```

## 五、大纲格式

```markdown
# 《项目名》10集开篇大纲

## 基本信息
| 项目 | 内容 |
|------|------|
| 项目标识 | xxx-xxx-YYMMDD |
| 类型/题材 | 类型 / 题材 / 视角 |
| 集数 | 10 集（开篇包） |
| 单集时长 | ≤2 分钟 |
| 单集格式 | 不限场景数量 |

## 一、故事简介
**一句话版本**：（一句话概括核心卖点）
**故事概要**：（完整故事线，200字以内）

## 二、杀必死/【skip】全集规划
（表格，见上方）

## 三、分集大纲
### 第N集：标题
**场景设定**：地点 - 时间 (内/外)。环境描写。
**出场人物**：角色列表
**核心互动**：本集发生什么（100字以内）
**关键转折**：结尾悬念/反转是什么
**杀必死/【skip】**：角色 / 描述 / 是否skip
```

## 六、剧本格式

### 文件头

```markdown
# 《项目名》第N集：标题

**项目标识**：xxx-xxx-YYMMDD
**感情线阶段**：当前阶段描述
**本集类型**：普通集 / skip集
**本集节点（来自大纲）**：
- 冲突/阻碍：
- 核心互动：
- 爽点：
- 结尾钩子：
```

### 正文写法

```markdown
FADE IN:

1. 场景名 - 时间 (内/外)

环境描写。只写镜头看得到的东西。

角色名（景别）——动作/状态描写。

**角色名**
（表演提示）
「台词内容。」

**角色名**
(OS.)    ← 内心独白用 OS.
「独白内容。」

【SKIP】        ← 如果是skip集

DISSOLVE TO:    ← skip后的跳转

事后场景。

FADE OUT.
```

### 尾部核查表

每集末尾必须附一个节点核查表：

```markdown
## 本集节点核查（编辑用）

| 节点 | 位置 / 时间点 | 状态 |
|------|-------------|------|
| ⭐ 开场钩子 | 场景开头，xxx | ✅ |
| ⭐ 冲突/阻碍 | 约第xx秒，xxx | ✅ |
| ⭐ 核心互动 | 约第xx秒，xxx | ✅ |
| ⭐ 爽点 | 约第xx秒，xxx | ✅ |
| ⭐ 结尾钩子 | 场景末尾，xxx | ✅ |
| ⭐ 杀必死场景 | 约第xx秒，类型：xxx | ✅ |
| 【skip】使用 | skip集：有/无，描述 | ✅/— |
| 完整互动 | 全集 | ✅ |
| 剧本长度 | xx行（普通集40-80行 / skip集20-55行） | ✅ |
```

## 七、常见退回原因

1. **skip 集没写事后场景** → 必须有，且事后必须有信息增量
2. **skip 前铺垫不够** → 临界点要有足够的情绪/动作积累，不能突兀跳入
3. **普通集没有杀必死** → 每集都要有，类型可以是视觉型/氛围型/肢体接触型
4. **动作行写文学修辞** → "她的眼神像深渊" ✘ → "她盯着我，没有眨眼" ✔
5. **普通集超过 80 行** → 压缩，2 分钟短剧不需要长篇
6. **skip 集没有缩短篇幅** → skip 集正文必须比普通集短 30%-50%，为 nsfw 续写预留空间
7. **连续两集 skip** → 中间必须隔至少 1 集普通集
8. **大纲没有 skip 规划表** → 必须有，在"杀必死/【skip】全集规划"章节
